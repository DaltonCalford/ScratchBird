# Firebird SQL - Tables and Constraints

> Emulation behavior: SQL is parsed by the dialect parser, translated to SBLR, executed by the ScratchBird engine, and results are formatted back to the client protocol.
> Emulated databases are metadata-only schemas; no physical database files are created. Unsupported features are called out in "Known Limitations" sections.

## Overview

Tables are the fundamental data storage structures in Firebird SQL. ScratchBird's Firebird emulation supports table creation, modification, and deletion using Firebird-compatible syntax, including Firebird-specific features like temporary tables and the `RECREATE` statement.

**Key Features:**
- CREATE TABLE with column and table constraints
- GLOBAL TEMPORARY tables with ON COMMIT options
- OR REPLACE and OR ALTER modifiers
- ALTER TABLE for schema modifications
- Full constraint support including PRIMARY KEY, FOREIGN KEY, UNIQUE, CHECK, and NOT NULL
- Computed columns and identity columns

**Important**: While the Firebird parser accepts most DDL syntax, some features are limited by the V2 pipeline (semantic analyzer, bytecode generator, and executor). These limitations are documented in the "Known Limitations" section.

## CREATE TABLE

### Description

Creates a new table with specified columns and constraints. Firebird supports several table creation modifiers including OR REPLACE (drop and recreate if exists), OR ALTER (alter if exists, create if not), and GLOBAL TEMPORARY for session-scoped temporary tables.

### Syntax

```sql
CREATE [ OR REPLACE | OR ALTER ] [ GLOBAL TEMPORARY ] TABLE table_name (
    column_definition [, column_definition ...]
    [, table_constraint ...]
)
[ ON COMMIT { DELETE ROWS | PRESERVE ROWS } ]
```

#### Column Definition

```sql
column_name data_type
    [ COLLATE collation_name ]
    [ column_constraint ... ]
```

#### Column Constraints

```sql
[ CONSTRAINT constraint_name ]
{
    NOT NULL |
    NULL |
    PRIMARY KEY |
    UNIQUE |
    CHECK ( condition ) |
    DEFAULT default_value |
    REFERENCES ref_table [ ( ref_column ) ]
        [ ON DELETE { CASCADE | SET NULL | SET DEFAULT | NO ACTION } ]
        [ ON UPDATE { CASCADE | SET NULL | SET DEFAULT | NO ACTION } ] |
    GENERATED [ ALWAYS | BY DEFAULT ] AS IDENTITY |
    COMPUTED [ BY ] ( expression )
}
```

#### Table Constraints

```sql
[ CONSTRAINT constraint_name ]
{
    PRIMARY KEY ( column_name [, ...] ) |
    UNIQUE ( column_name [, ...] ) |
    FOREIGN KEY ( column_name [, ...] )
        REFERENCES ref_table [ ( ref_column [, ...] ) ]
        [ ON DELETE { CASCADE | SET NULL | SET DEFAULT | NO ACTION } ]
        [ ON UPDATE { CASCADE | SET NULL | SET DEFAULT | NO ACTION } ] |
    CHECK ( condition )
}
```

### Parameters

- **OR REPLACE**: Drop the table if it exists, then create it
- **OR ALTER**: Alter the table if it exists, create it if it doesn't (Firebird-specific)
- **GLOBAL TEMPORARY**: Create a temporary table visible to all sessions but with session-specific data
- **ON COMMIT DELETE ROWS**: Clear temporary table data at transaction commit (default)
- **ON COMMIT PRESERVE ROWS**: Keep temporary table data after transaction commit
- **COLLATE**: Specify collation for character columns
- **GENERATED AS IDENTITY**: Auto-incrementing column (SQL standard syntax)
- **COMPUTED BY**: Define a computed/calculated column

### Examples

#### Basic Table Creation

```sql
CREATE TABLE employees (
    employee_id INTEGER NOT NULL,
    first_name VARCHAR(50),
    last_name VARCHAR(50) NOT NULL,
    hire_date DATE,
    salary DECIMAL(10, 2)
);
```

#### Table with Primary Key and Constraints

```sql
CREATE TABLE customers (
    customer_id INTEGER NOT NULL PRIMARY KEY,
    email VARCHAR(255) NOT NULL UNIQUE,
    company_name VARCHAR(100) NOT NULL,
    credit_limit DECIMAL(12, 2) DEFAULT 0,
    created_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT chk_credit CHECK (credit_limit >= 0)
);
```

#### Table with Foreign Key

```sql
CREATE TABLE orders (
    order_id INTEGER NOT NULL,
    customer_id INTEGER NOT NULL,
    order_date DATE NOT NULL,
    total_amount DECIMAL(12, 2),
    PRIMARY KEY (order_id),
    CONSTRAINT fk_customer FOREIGN KEY (customer_id)
        REFERENCES customers (customer_id)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);
```

#### Table with Identity Column

```sql
CREATE TABLE products (
    product_id INTEGER GENERATED BY DEFAULT AS IDENTITY,
    product_name VARCHAR(100) NOT NULL,
    unit_price DECIMAL(10, 2) NOT NULL,
    in_stock INTEGER DEFAULT 0,
    PRIMARY KEY (product_id)
);
```

#### Table with Computed Column

```sql
CREATE TABLE invoices (
    invoice_id INTEGER NOT NULL PRIMARY KEY,
    subtotal DECIMAL(12, 2) NOT NULL,
    tax_rate DECIMAL(5, 4) DEFAULT 0.0825,
    tax_amount COMPUTED BY (subtotal * tax_rate),
    total_amount COMPUTED BY (subtotal + (subtotal * tax_rate))
);
```

#### Global Temporary Table

```sql
CREATE GLOBAL TEMPORARY TABLE session_cart (
    item_id INTEGER NOT NULL,
    product_id INTEGER NOT NULL,
    quantity INTEGER NOT NULL,
    unit_price DECIMAL(10, 2) NOT NULL
)
ON COMMIT DELETE ROWS;
```

This creates a temporary table where each session has its own data, and data is cleared when the transaction commits.

#### Temporary Table with Preserved Rows

```sql
CREATE GLOBAL TEMPORARY TABLE temp_calculations (
    calc_id INTEGER NOT NULL PRIMARY KEY,
    input_value DECIMAL(18, 6),
    result_value DECIMAL(18, 6)
)
ON COMMIT PRESERVE ROWS;
```

Data persists across transactions within the same session.

#### Using OR REPLACE

```sql
CREATE OR REPLACE TABLE config_settings (
    setting_name VARCHAR(100) NOT NULL PRIMARY KEY,
    setting_value VARCHAR(500),
    last_updated TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

If the table already exists, it will be dropped and recreated.

#### Complex Table with Multiple Constraints

```sql
CREATE TABLE employee_projects (
    employee_id INTEGER NOT NULL,
    project_id INTEGER NOT NULL,
    role VARCHAR(50) NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE,
    hours_allocated DECIMAL(6, 2),

    CONSTRAINT pk_emp_proj PRIMARY KEY (employee_id, project_id),
    CONSTRAINT fk_employee FOREIGN KEY (employee_id)
        REFERENCES employees (employee_id)
        ON DELETE CASCADE,
    CONSTRAINT fk_project FOREIGN KEY (project_id)
        REFERENCES projects (project_id)
        ON DELETE CASCADE,
    CONSTRAINT chk_dates CHECK (end_date IS NULL OR end_date >= start_date),
    CONSTRAINT chk_hours CHECK (hours_allocated > 0)
);
```

#### Table with Character Set and Collation

```sql
CREATE TABLE multilingual_content (
    content_id INTEGER NOT NULL PRIMARY KEY,
    title VARCHAR(200) COLLATE UNICODE,
    description VARCHAR(1000) COLLATE UNICODE,
    language_code CHAR(2) NOT NULL
);
```

### Usage Notes

1. **Temporary Tables**: GLOBAL TEMPORARY tables are visible to all sessions, but each session has its own private data. The table structure is shared, but the data is not.

2. **ON COMMIT Behavior**:
   - DELETE ROWS (default): Data is cleared at each COMMIT
   - PRESERVE ROWS: Data persists until the session ends

3. **OR REPLACE vs OR ALTER**:
   - OR REPLACE: Drops and recreates the entire table (data is lost)
   - OR ALTER: Firebird-specific; alters existing table structure or creates if doesn't exist

4. **Computed Columns**: Cannot be modified by INSERT/UPDATE statements; values are calculated automatically based on the expression.

5. **Identity Columns**:
   - GENERATED ALWAYS: Value must always be generated, cannot be explicitly inserted
   - GENERATED BY DEFAULT: Generated by default, but can be overridden

6. **Constraint Naming**: Always name constraints using CONSTRAINT clause for easier management and clearer error messages.

### Current Implementation Limitations

While the parser accepts full CREATE TABLE syntax:

- **Temporary Table Behavior**: ON COMMIT DELETE/PRESERVE ROWS options are parsed but not fully enforced by the V2 executor
- **Constraint Enforcement**: Many constraints are parsed but not fully validated during execution
- **Computed Columns**: COMPUTED BY is parsed but may not be fully implemented in execution
- **Identity Columns**: GENERATED AS IDENTITY is parsed but implementation status varies

See "Known Limitations" section for complete details.

## ALTER TABLE

### Description

Modifies the structure of an existing table. You can add columns, drop columns, rename columns, add constraints, or drop constraints. Firebird's ALTER TABLE is more limited than some other SQL databases - many operations require separate statements.

### Syntax

```sql
ALTER TABLE table_name
{
    ADD [ COLUMN ] column_definition |
    DROP [ COLUMN ] column_name |
    ALTER [ COLUMN ] column_name TO new_column_name |
    ADD table_constraint |
    DROP CONSTRAINT constraint_name
}
```

### Parameters

- **ADD COLUMN**: Add a new column to the table
- **DROP COLUMN**: Remove an existing column
- **ALTER COLUMN ... TO**: Rename a column
- **ADD constraint**: Add a table-level constraint
- **DROP CONSTRAINT**: Remove a named constraint

### Examples

#### Add a Column

```sql
ALTER TABLE employees ADD COLUMN email VARCHAR(255);
```

#### Add a Column with Constraints

```sql
ALTER TABLE employees
    ADD COLUMN phone_number VARCHAR(20) NOT NULL DEFAULT '';
```

#### Drop a Column

```sql
ALTER TABLE employees DROP COLUMN phone_number;
```

You can also use the optional COLUMN keyword:

```sql
ALTER TABLE employees DROP phone_number;
```

#### Rename a Column

```sql
ALTER TABLE employees ALTER COLUMN email TO email_address;
```

Or without the COLUMN keyword:

```sql
ALTER TABLE employees ALTER email TO email_address;
```

#### Add a Table Constraint

```sql
ALTER TABLE employees
    ADD CONSTRAINT chk_salary CHECK (salary >= 0);
```

#### Add a Foreign Key Constraint

```sql
ALTER TABLE orders
    ADD CONSTRAINT fk_customer
    FOREIGN KEY (customer_id)
    REFERENCES customers (customer_id)
    ON DELETE CASCADE;
```

#### Drop a Constraint

```sql
ALTER TABLE employees DROP CONSTRAINT chk_salary;
```

#### Multiple Operations (Require Separate Statements)

```sql
-- Add two columns (requires two statements)
ALTER TABLE products ADD COLUMN manufacturer VARCHAR(100);
ALTER TABLE products ADD COLUMN model_number VARCHAR(50);

-- Rename and add constraint (requires two statements)
ALTER TABLE products ALTER COLUMN price TO unit_price;
ALTER TABLE products ADD CONSTRAINT chk_price CHECK (unit_price > 0);
```

### Usage Notes

1. **Single Operation Per Statement**: Unlike some SQL databases, Firebird typically requires one ALTER TABLE operation per statement.

2. **Column Renaming**: Use ALTER COLUMN ... TO syntax for renaming. This is Firebird-specific.

3. **Cannot Modify Column Type**: The current implementation doesn't support changing a column's data type directly. You would need to add a new column, migrate data, drop the old column, and rename the new one.

4. **Adding NOT NULL**: Be careful when adding NOT NULL constraints to existing tables with data - you need to provide a DEFAULT value or ensure all existing rows have non-NULL values.

5. **Constraint Names**: When adding constraints, always provide a name using CONSTRAINT clause for easier management.

6. **Dropping Columns with Dependencies**: Dropping a column that's referenced by views, indexes, or constraints may require dropping those dependencies first.

### Current Implementation Limitations

- **Limited Actions**: Parser only supports ADD COLUMN, DROP COLUMN, ALTER COLUMN TO (rename), ADD CONSTRAINT, and DROP CONSTRAINT
- **Not Implemented**: Column type changes, SET DEFAULT, DROP DEFAULT, and other Firebird ALTER TABLE variants are not parsed
- **Partial Execution**: Some parsed operations may not be fully executed by the V2 pipeline

See "Known Limitations" section for details.

## DROP TABLE

### Description

Removes a table from the database, including all its data, indexes, and constraints. This is a permanent operation that cannot be undone.

### Syntax

```sql
DROP TABLE table_name
```

### Parameters

- **table_name**: The name of the table to drop

### Examples

#### Drop a Table

```sql
DROP TABLE old_customers;
```

#### Drop Multiple Tables (Separate Statements)

```sql
DROP TABLE temp_data;
DROP TABLE archive_2023;
DROP TABLE staging_imports;
```

#### Drop with Transaction Control

```sql
-- Start a transaction
SET TRANSACTION;

-- Drop tables
DROP TABLE obsolete_table;
DROP TABLE another_old_table;

-- Commit if successful, or rollback if there's an error
COMMIT;
```

### Usage Notes

1. **Permanent Operation**: DROP TABLE permanently deletes all data and structure. Make sure you have backups if needed.

2. **Dependencies**: You may need to drop dependent objects first:
   - Views that reference the table
   - Foreign key constraints from other tables
   - Triggers on the table

3. **No IF EXISTS**: Standard Firebird doesn't support `DROP TABLE IF EXISTS`. You'll get an error if the table doesn't exist.

4. **Transaction Context**: DROP TABLE is a DDL operation that affects the database schema.

5. **Temporary Tables**: You can drop GLOBAL TEMPORARY tables the same way as regular tables. The structure is removed for all sessions.

### Current Implementation Limitations

**Status**: Implemented

The DROP TABLE statement is parsed, generates `DROP_TABLE` opcode with IF EXISTS and CASCADE flags, and is executed by the executor.

## TRUNCATE TABLE

### Description

Firebird SQL does not have a TRUNCATE TABLE statement. This is a dialect design decision - Firebird uses DELETE FROM without a WHERE clause to remove all rows from a table.

**Status**: Not available (by dialect design)

### Alternative: DELETE FROM

To remove all rows from a table in Firebird:

```sql
DELETE FROM table_name;
```

### Comparison with TRUNCATE

In databases that support TRUNCATE TABLE, it typically:
- Removes all rows faster than DELETE
- Cannot be rolled back in some databases
- Resets auto-increment counters
- Doesn't fire triggers
- Requires fewer transaction log entries

In Firebird, `DELETE FROM table_name`:
- Removes all rows
- Can be rolled back (within a transaction)
- Fires DELETE triggers for each row
- Preserves generator/sequence values
- Creates full transaction log entries

### Examples

#### Remove All Rows

```sql
-- Firebird syntax (no WHERE clause)
DELETE FROM temporary_data;
```

#### Remove All Rows Within Transaction

```sql
SET TRANSACTION;

DELETE FROM staging_table;

-- Review the change, then commit or rollback
COMMIT;
-- or: ROLLBACK;
```

#### Remove All Rows and Reset Generator

If you need to reset an identity/generator value:

```sql
-- Delete all rows
DELETE FROM my_table;

-- Reset the generator (if you're using one)
-- Note: This syntax may not be available in current parser
-- ALTER SEQUENCE gen_my_table_id RESTART WITH 1;
```

### Performance Considerations

For very large tables, DELETE FROM (without WHERE) can be slow because:
1. It processes each row individually
2. Fires triggers for each row
3. Creates full transaction log entries
4. Maintains MVCC versions

For better performance when clearing large tables:
1. Consider using DROP TABLE and CREATE TABLE instead
2. Use WHERE clause to delete in batches within a loop
3. Adjust transaction settings for bulk operations

## Known Limitations

### Partial Implementation

**CREATE TABLE**
- Temporary table behavior (ON COMMIT DELETE/PRESERVE ROWS) is parsed but not fully enforced by the V2 executor
- Many constraint types are parsed but not fully validated during execution
- Computed columns (COMPUTED BY) are parsed but implementation is incomplete
- Identity columns (GENERATED AS IDENTITY) are parsed but may not work as expected
- Many column and table options are accepted by the parser but ignored by the V2 pipeline

**ALTER TABLE**
- Only basic operations supported: ADD COLUMN, DROP COLUMN, ALTER COLUMN TO (rename), ADD/DROP CONSTRAINT
- Cannot modify column data types
- Cannot modify column defaults after creation (SET DEFAULT, DROP DEFAULT not parsed)
- Cannot modify NOT NULL constraints after creation
- Cannot rename table (RENAME TO not supported)
- Many Firebird ALTER TABLE variants are not parsed and will cause errors

### DROP TABLE

**DROP TABLE**
- Parser accepts DROP TABLE and generates AST with IF EXISTS flag
- Bytecode generator emits `DROP_TABLE` opcode with name, IF EXISTS, and CASCADE flags
- Executor processes DROP TABLE normally

### Missing Features

**TRUNCATE TABLE**
- Not available by dialect design (Firebird doesn't support TRUNCATE)
- Use `DELETE FROM table_name` instead

**ALTER TABLE Extended Operations**
- ALTER COLUMN SET DATA TYPE - cannot change column type
- ALTER COLUMN SET DEFAULT - cannot modify defaults
- ALTER COLUMN DROP DEFAULT - cannot remove defaults
- ALTER COLUMN SET NOT NULL - cannot add NOT NULL to existing column
- ALTER COLUMN DROP NOT NULL - cannot remove NOT NULL
- RENAME TO - cannot rename table
- ADD CONSTRAINT variants for advanced constraints

**CREATE TABLE Advanced Features**
- EXTERNAL FILE tables - not supported
- Full constraint enforcement in executor
- Complete temporary table isolation and cleanup
- Computed column full execution
- Generated column expressions (beyond basic IDENTITY)

### Specification Deltas

**V2 Pipeline Limitations**
The Firebird parser generates AST v2 nodes, which are then processed by:
1. SemanticAnalyzerV2 - validates and annotates the AST
2. BytecodeGeneratorV2 - converts to SBLR bytecode
3. Executor - executes the bytecode

Many constraints, options, and features are lost or ignored during this pipeline:
- Complex constraints (multi-column checks, advanced referential actions) may not be enforced
- Table options (character sets, collations) may not be fully applied
- Computed column expressions may not execute correctly
- Identity generation may not work as expected

**Temporary Tables**
- Parser accepts GLOBAL TEMPORARY TABLE syntax
- ON COMMIT DELETE ROWS / PRESERVE ROWS options are parsed
- Actual temporary table behavior and cleanup is not fully implemented
- Session isolation may not work as expected

### Workarounds

**For Type Changes**:
```sql
-- Instead of ALTER COLUMN SET DATA TYPE (not supported)
ALTER TABLE mytable ADD COLUMN new_col NEW_TYPE;
UPDATE mytable SET new_col = CAST(old_col AS NEW_TYPE);
ALTER TABLE mytable DROP COLUMN old_col;
ALTER TABLE mytable ALTER COLUMN new_col TO old_col;
```

**For Full Table Clear**:
```sql
-- Instead of TRUNCATE TABLE (not available)
-- Option 1: Simple delete
DELETE FROM mytable;

-- Option 2: Recreate table (faster for large tables)
CREATE OR REPLACE TABLE mytable (
    -- same structure
);
```
