# Section 19: Security Model

Status: current_authority

## Purpose

This section defines the current ScratchBird security bootstrap, encryption, authentication, key material, certificate, audit, and security hardening rules that must hold before a listener or engine session is exposed to work.

## Core invariants

- Security bootstrap is fail-closed.
- Listener exposure must not begin before required security bootstrap completes.
- Key material and certificates are bootstrap authority, not catalog authority.
- Authentication is completed before engine session attach is considered successful.
- Signed module policy applies to loadable authentication extensions.
- Security configuration is owned by bootstrap configuration, not ad hoc SQL mutation.
- Audit and forensic surfaces are derived security evidence surfaces; they are not override channels.

## Scope

This section owns:

- security bootstrap ordering
- pre-decryption metadata boundary
- encryption and key management rules
- key and certificate handling rules
- authentication method contracts
- signed authentication module ABI rules
- engine authentication hardening and manager option rules
- current PKI lifecycle rules for local and configured channels
- audit and forensic access rules
- threat model and security control matrix

## Out of scope

This section does not claim implemented authority for:

- automated distributed trust-fabric governance beyond current configured channels
- remote capsule federation or autonomous supply-chain policy refresh
- any security model that assumes WAL-owned truth

## Current Beta 1 implementation subset

For Beta 1 package `06`, the implementation-closing subset inside this section
is bounded to:

- local-engine and single-node service security bootstrap
- bootstrap-managed key and certificate sources plus explicit local reload or
  rotation paths already supported by the current runtime
- HBA, auth-manager, plugin-admission, lockout, MFA, and manager-control
  authentication for the admitted local-engine auth families
- local users, roles, groups, memberships, permission cache, and local
  row/column/domain masking or sandbox enforcement
- audit and forensic access gating for local operator-visible evidence

## Explicit non-Beta 1 boundaries

The following section-19 surfaces are not Beta 1 implementation targets for
package `06` and must remain fail-closed or preparatory substrate only:

- cluster-shared identity propagation and remote authorization-drift repair
- quorum secret shard distribution, unseal, escrow, and cluster rotation
- distributed trust-fabric governance and cluster-aware certificate rollout
- enterprise or external auth-provider families outside the admitted local
  Beta 1 support set
