## Update 2026-03-28: Current code-backed section boundary

Section `18` is normalized to the code-backed `partial` standard.

Current proven authority in code:
- `CatalogManager::IndexType` exposes the admitted named-family surface, and `IndexFactory` is the actual create/open/close and capability authority.
- Shared runtime backends exist, but they are an implementation substrate rather than a demotion of named-family authority.
- Every admitted named `IndexType` remains an independently primary planner, metrics, observability, and maintenance identity even when multiple names route through one concrete runtime class.
- The current shared runtime classes include:
  - `BTREE`
  - `HASH`
  - `LSM`
  - `GIN`
  - `GIST`
  - `BRIN`
  - `RTREE`
  - `SPGIST`
  - `BITMAP`
  - `COLUMNSTORE`
  - `HNSW`
  - `INVERTED`
- Catalog-backed `createIndex(...)` with key columns, include columns, expression payload, partial predicate payload, tablespace-aware root allocation, dependency creation, and immediate active-state publication is real.
- Optimizer lowering, typed family metrics packets, queryability state, and fail-closed generic operator behavior are real.
- MGA cleanup integration is real through `IndexFactory` runtime classes and garbage-collector cleanup-family classification.

Current bounded or unproven areas:
- some named families still share runtime backends, but shared lowering no
  longer demotes named-family planner or metrics identity
- generic online or concurrent build exposure and broad maintenance semantics are not closed from the current code pass
- broader Beta 2 planner search, adaptive ranking, and family-universal
  operator hardening remain outside the current code-backed proof
