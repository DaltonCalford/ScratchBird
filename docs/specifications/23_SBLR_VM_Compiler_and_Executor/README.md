# Section 23 - SBLR VM Compiler and Executor

Status: current_authority

## Current authority

The real implementation surface is the compiler and optimizer path centered on `QueryCompilerV3`, `QueryPlanner::planStatement(...)`, runtime-plan payload serialization, `VNextPlanCache`, the current validator bridge, and executor-side plan or explain integration.

## Section scope

Section `23` is authoritative for:
- planner front door and statement-planning API
- bytecode load, validator acceptance, and compiler finalize pipeline
- optimizer architecture, access-path ordering, join search, and index-family lowering
- runtime-plan payload and diagnostics formation
- plan-cache and invalidation behavior
- execution-time memory-budget and spill-planning metadata

## Explicit non-authority

Section `23` is not current authority for:
- a separate stable VM ABI layer
- full distributed scheduling or distributed-read orchestration
- a complete compute-capsule subsystem
- a complete native-compilation lifecycle contract
- a dedicated bulk-load or COPY execution subsystem beyond explicitly documented current edges

The `NORMATIVE_*CHECKLIST` files in this section are explicit unsupported-boundary or future worklist files, not current implementation proof.
