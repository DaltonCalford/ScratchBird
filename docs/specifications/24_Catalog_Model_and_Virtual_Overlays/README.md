# Section 24 - Catalog Model and Virtual Overlays

Status: current_authority

## Current authority

Section `24` is the canonical current-state authority for:
- persisted catalog row families owned by `CatalogManager`
- virtual overlay exposure owned by `VirtualCatalogRouter` and registered handlers
- startup-time virtual catalog initialization
- current charset and timezone resource-loading anchors
- commit-bound schema publication and metadata invalidation boundaries already defined in this section

## Scope

Current section authority covers:
- persisted catalog family inventory
- core object, engine-specific, and runtime-context catalog exposure
- system object visibility and profile-gated overlay registration
- startup and installation anchors for current catalog visibility
- metadata and statistics helper contracts used by parsers and clients

## Current implementation summary

- `CatalogManager` is the durable root for current catalog row-family
  persistence.
- `VirtualCatalogRouter` plus registered handlers are the current overlay
  exposure substrate.
- current code already proves transactional metadata publication, dependency
  replacement, schema-epoch history, and remote-management cluster-policy row
  families
- current code now proves `config_key`, `config_value`, `config_change_log`,
  `listener_profile`, `listener_binding`, `listener_emulation_binding`,
  `parser_pool_policy`, `listener_runtime_target`, and
  `listener_generation_record` as durable catalog families
- package `02` closed the target-local durable split between scalar config
  rows and dedicated listener-topology rows without changing overlay routing
  ownership

## Explicit boundaries

Section `24` is not current authority for:
- a full branch or changeset catalog object model
- universal donor-engine overlay parity
- universal resource-bundle activation lifecycle
- full cluster-fabric, migration, replication, or remote-runtime semantics beyond persisted or virtual exposure boundaries

Those surfaces remain explicit unsupported or separately owned boundaries.

## Governing invariants inherited here

- ScratchBird is always in a transaction.
- `COMMIT` publishes committed catalog and schema state and immediately starts the next transaction.
- `ROLLBACK` retires uncommitted catalog and schema state and immediately starts the next transaction.
- `DDL` and `DML` follow the same MGA transaction rules.
- Catalog truth is UUID-based internally; name resolution is a user-layer concern.
- WAL is not authoritative for catalog publication or recovery semantics.
