# Benchmark Consolidated CSV Schema and Decision Workflow

## Status

Current code-backed authority with reconstructed commercial-grade detail.

## Purpose

This document defines the exact role of `matrix-comparison-unified.csv`, how it is generated, which metric families it contains, and how operators must use it for benchmark decisions.

## Authoritative Generator

The consolidated CSV is generated by:

- `ScratchBird-Benchmarks/scripts/generate-unified-comparison-csv.py`

This generator is authoritative for matrix-to-CSV projection.

## Inputs

The generator requires:

- `matrix-summary.json`

It may be invoked by:

- `--output-root <matrix root>`
- `--summary <path to matrix-summary.json>`

The default output path is:

- `<matrix root>/matrix-comparison-unified.csv`

## CSV Shape

The CSV has these fixed leading columns:

- `run_id`
- `suite`
- `metric`

After those, there is one column per requested engine in matrix-summary order.

This shape is not row-per-test. It is row-per-`(suite, metric)` with one value cell per engine.

## Engine Ordering Rule

Engine columns must preserve the request order from:

- `matrix-summary.json.engines_requested`

Duplicate engine names are removed while preserving first-seen order.

## Suite Ordering Rule

Rows must be grouped and sorted by:

1. requested suite order from `matrix-summary.json.suites_requested`
2. metric name within each suite

Unknown or extra suites sort after the requested suite list.

## Matrix Metric Families

The generator always emits matrix runtime metrics when suite-run records exist:

- `matrix.status`
- `matrix.exit_code`
- `matrix.duration_seconds`

These are derived from `matrix-summary.json.suite_runs[]`, not from raw suite JSON.

## Artifact Provenance Metric

When a suite result JSON is found, the CSV must emit:

- `artifact.result_json`

This value is the suite JSON path relative to the matrix output root.

That provenance field is mandatory for metric drill-down.

## Suite JSON Selection Rules

For each `(engine, suite)` pair, the generator selects one primary result JSON.

Selection rules are:

- if the suite is `regression`, prefer a file with `summary` in its name
- otherwise prefer a non-summary JSON file
- if no non-summary file exists, fall back to the first JSON candidate

This rule is authoritative for current CSV generation and must be preserved unless the artifact model is explicitly revised.

## Extracted Metric Families

The generator extracts different metric families depending on payload shape.

### Regression

From `payload.totals` it emits:

- `totals.*`

### Non-Regression Suites

From `payload.summary` it emits:

- `summary.*`

### Generic Result Collections

If `payload.results` is a list:

- `results.count`

If `payload.results` is a dictionary:

- `results.count`
- `results.<key>.count` for child lists

If `payload.test_results` is a list:

- `test_results.count`

Nested dictionaries are flattened using dot notation.

Lists are represented by counts, not embedded JSON.

## Value Rendering Rules

CSV values are rendered as:

- empty string for `null`
- `true` or `false` for booleans
- string form for all other scalar values

## High-Signal Metrics By Suite

### Regression

High-signal metrics are:

- `totals.total`
- `totals.passed`
- `totals.failed`
- `totals.errors`
- `totals.pass_rate`

### Stress

High-signal metrics are:

- `summary.total_tests`
- `summary.passed`
- `summary.failed`
- `summary.errors`
- `summary.total_duration_ms`

### ACID

High-signal metrics are:

- `summary.total`
- `summary.passed`
- `summary.failed`
- `summary.errors`
- `summary.by_category.*`

### Engine Differential

High-signal metrics are:

- `summary.total_tests`
- `summary.by_category.mysql_optimized`
- `summary.by_category.pg_optimized`
- `summary.by_category.fb_optimized`

### Index Comparison

High-signal metrics include:

- `summary.*`
- `summary.by_expectation_status.*`
- `summary.plan_capture_success`
- `matrix.duration_seconds`
- artifact provenance rows

## Decision Workflow

Operators must use the consolidated CSV in this order:

1. verify `matrix.status`
2. verify `matrix.exit_code`
3. verify correctness metrics for the suite
4. compare runtime and summary deltas
5. use `artifact.result_json` to inspect the source JSON when differences matter

The CSV is therefore a decision index, not the only source of truth.

## Pairwise Index-Comparison Boundary

The consolidated CSV does not replace pairwise normalized verdict artifacts.

For `index-comparison`, final directional comparative judgment still requires:

- `comparison-index-comparison/index-comparison-pairwise-*.json`

Use the CSV for:

- run integrity
- summary metric comparison
- artifact drill-down

Use the pairwise comparator artifacts for:

- `better`
- `equivalent`
- `worse`
- `fallback`
- `unsupported`
- `invalid`

## Rebuild Rule

If the matrix summary already exists, the consolidated CSV may be rebuilt without rerunning the suites by invoking the generator directly.

This rebuild path is authoritative and must produce the same row model as the matrix runner's integrated generation path.
