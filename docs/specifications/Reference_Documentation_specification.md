## How to use the matrix

The fastest path from here is:

- treat **ranks 1–20** as the active Beta 1 working set
- treat **ranks 21–40** as the Beta 2 design-and-method set
- treat **ranks 41–46** as the paper stack that sharpens the spec language and test strategy

The most important process rule is to assign each donor a **single declared role** in the spec tree: semantic donor, algorithm donor, migration donor, interoperability foil, control-plane donor, security/audit donor, fault-testing donor, or literature donor. That keeps the library from turning into donor sprawl while your specs are still being frozen. Your current section style already emphasizes explicit ownership and explicit non-guarantees instead of silent topic collapse, so this donor-role discipline fits the project well.

A useful next artifact would be a **donor control sheet** with one row per donor and three extra fields: `authoritative topics`, `non-authoritative topics`, and `evidence imported into specs`
