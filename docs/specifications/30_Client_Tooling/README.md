# Section 30 - Client Tooling

Status: current_authority

## Scope

Section 30 defines the shipped ScratchBird client-tooling contract for linked APIs, standalone tools, connectivity profiles, maintained driver lanes, result and error behavior, installation profiles, installer-driven analytical/domain UDR package selection, and bounded native control surfaces.

## Current authority

The current implementation authority for section 30 is the combination of:
- the maintained client and driver code in `ScratchBird-driver`
- the shared connection, protocol, and session contracts in sections `26`, `27`, `28`, and `29`
- the current stable linked and tool-facing contracts documented in this section

Section 30 is implementation authority for the client-facing contract. It is not a planning surface.

## Non-goals

Section 30 does not claim:
- universal feature parity across every language driver
- unmanaged plugin ABI stability for internal listener or IPC contracts
- automatic parity between linked APIs and every command-line or driver surface
- active support for migration, passthrough, replication, or forensic control flows beyond the explicitly documented shipped contract

## Governing invariants inherited here

- ScratchBird is always in a transaction.
- `COMMIT` immediately starts the next transaction.
- `ROLLBACK` immediately starts the next transaction.
- `START TRANSACTION` changes transaction defaults and attributes.
- `AUTOCOMMIT` means post-success commit only.
- `DDL` and `DML` follow the same transaction rules.
- ScratchBird uses MGA transaction handling, not WAL-authoritative durability.
