## CREATE TABLE

**Location:** `parseCreateTable()` at line 651

### Syntax (BNF)

```bnf
CREATE TABLE table_name (
    { column_definition | table_constraint } [, ...]
) [ TABLESPACE tablespace_name ]

column_definition ::=
    column_name data_type
    [ NOT NULL | NULL ]
    [ DEFAULT expression ]
    [ PRIMARY KEY ]
    [ UNIQUE ]
    [ CHECK ( expression ) ]
    [ REFERENCES table_name [ ( column_name [, ...] ) ]
        [ ON DELETE { CASCADE | RESTRICT | SET NULL | SET DEFAULT | NO ACTION } ]
        [ ON UPDATE { CASCADE | RESTRICT | SET NULL | SET DEFAULT | NO ACTION } ]
    ]
    [ GENERATED { ALWAYS | BY DEFAULT } AS IDENTITY ]
    [ GENERATED ALWAYS AS ( expression ) [ STORED | VIRTUAL ] ]

table_constraint ::=
    [ CONSTRAINT constraint_name ]
    { PRIMARY KEY ( column_name [, ...] ) |
      UNIQUE ( column_name [, ...] ) |
      FOREIGN KEY ( column_name [, ...] )
        REFERENCES table_name [ ( column_name [, ...] ) ]
        [ ON DELETE { CASCADE | RESTRICT | SET NULL | SET DEFAULT | NO ACTION } ]
        [ ON UPDATE { CASCADE | RESTRICT | SET NULL | SET DEFAULT | NO ACTION } ]
        [ [ NOT ] DEFERRABLE ]
        [ INITIALLY { DEFERRED | IMMEDIATE } ] |
      CHECK ( expression )
    }
```

### Column-Level Constraints

1. **NOT NULL / NULL**
   - Specifies whether column accepts NULL values
   - Default: NULL (nullable)

2. **DEFAULT**
   - Provides default value for column
   - Accepts any valid expression

3. **PRIMARY KEY**
   - Designates column as primary key
   - Implies NOT NULL and UNIQUE
   - Only one primary key per table (column-level or table-level)

4. **UNIQUE**
   - Ensures column values are unique across all rows

5. **CHECK**
   - Enforces boolean condition on column values
   - Syntax: `CHECK ( boolean_expression )`

6. **REFERENCES (Foreign Key)**
   - Creates foreign key constraint to another table
   - Syntax: `REFERENCES table_name [ ( column_name ) ]`
   - Optional actions:
     - `ON DELETE { CASCADE | RESTRICT | SET NULL | SET DEFAULT | NO ACTION }`
     - `ON UPDATE { CASCADE | RESTRICT | SET NULL | SET DEFAULT | NO ACTION }`

7. **GENERATED AS IDENTITY**
   - Creates auto-incrementing identity column
   - Variants:
     - `GENERATED ALWAYS AS IDENTITY` - Always generated (no manual insert)
     - `GENERATED BY DEFAULT AS IDENTITY` - Generated by default (manual override allowed)
   - Implies NOT NULL

8. **GENERATED AS (expression)**
   - Creates computed/generated column
   - Syntax: `GENERATED ALWAYS AS ( expression ) [ STORED | VIRTUAL ]`
   - Must use `ALWAYS` (not `BY DEFAULT`)
   - Storage modes:
     - `STORED` - Computed value physically stored (default)
     - `VIRTUAL` - Computed on-the-fly (not yet fully supported)

### Table-Level Constraints

1. **PRIMARY KEY**
   - Syntax: `PRIMARY KEY ( column_name [, ...] )`
   - Composite primary key on multiple columns
   - Optional: `CONSTRAINT constraint_name`

2. **UNIQUE**
   - Syntax: `UNIQUE ( column_name [, ...] )`
   - Composite unique constraint on multiple columns
   - Optional: `CONSTRAINT constraint_name`

3. **FOREIGN KEY**
   - Syntax: `FOREIGN KEY ( column_list ) REFERENCES table_name ( column_list )`
   - Optional actions:
     - `ON DELETE { CASCADE | RESTRICT | SET NULL | SET DEFAULT | NO ACTION }`
     - `ON UPDATE { CASCADE | RESTRICT | SET NULL | SET DEFAULT | NO ACTION }`
   - Deferred constraint checking (ALPHA Phase 1):
     - `[ NOT ] DEFERRABLE` - Controls if constraint can be deferred
     - `INITIALLY { DEFERRED | IMMEDIATE }` - Sets initial checking mode
   - Optional: `CONSTRAINT constraint_name`

4. **CHECK**
   - Syntax: `CHECK ( expression )`
   - Table-level CHECK constraint (WP-6 PARSE-1)
   - Optional: `CONSTRAINT constraint_name`

### Table Options

- **TABLESPACE** - Specifies tablespace for table storage
  - Syntax: `TABLESPACE tablespace_name`
  - Phase 2 Task 2.3 feature

### Examples

```sql
-- Basic table with column constraints
CREATE TABLE users (
    id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL,
    age INT CHECK (age >= 0 AND age <= 150),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    profile_id INT REFERENCES profiles(id) ON DELETE CASCADE
);

-- Table with table-level constraints
CREATE TABLE orders (
    order_id INT,
    customer_id INT,
    product_id INT,
    quantity INT,
    PRIMARY KEY (order_id),
    FOREIGN KEY (customer_id) REFERENCES customers(id)
        ON DELETE RESTRICT
        DEFERRABLE INITIALLY DEFERRED,
    FOREIGN KEY (product_id) REFERENCES products(id)
        ON UPDATE CASCADE,
    CHECK (quantity > 0),
    CONSTRAINT valid_order UNIQUE (customer_id, product_id)
) TABLESPACE fast_storage;

-- Generated columns
CREATE TABLE rectangles (
    id INT PRIMARY KEY,
    width DECIMAL(10,2),
    height DECIMAL(10,2),
    area DECIMAL(10,2) GENERATED ALWAYS AS (width * height) STORED
);

-- Identity columns
CREATE TABLE sequences_demo (
    id INT GENERATED ALWAYS AS IDENTITY,
    code INT GENERATED BY DEFAULT AS IDENTITY,
    name VARCHAR(100)
);
```

- Parser location: lines 651-741

- Table constraint parsing: parseTableConstraint() lines 1193-1494
- Foreign key actions parsed as identifiers with special handling for multi-word actions (SET NULL, NO ACTION, etc.)
- DEFERRABLE constraints fully supported (ALPHA Phase 1)

## CREATE INDEX

**Location:** `parseCreateIndex()` at line 743

### Syntax (BNF)

```bnf
CREATE [ UNIQUE ] INDEX index_name
    ON table_name
    [ USING index_type ]
    ( { column_name | ( expression ) } [, ...] )
    [ WHERE condition ]
    [ TABLESPACE tablespace_name ]

index_type ::=
    BTREE | HASH | LSM | GIN | GIST | BITMAP | COLUMNSTORE
```

### Options

1. **UNIQUE**
   - Creates unique index
   - Ensures indexed columns have unique values

2. **USING index_type**
   - Specifies index method (LSM Integration Phase 2 Task 2.1)
   - Supported types:
     - `BTREE` - B-Tree index (default)
     - `HASH` - Hash index
     - `LSM` - Log-Structured Merge tree
     - `GIN` - Generalized Inverted Index
     - `GIST` - Generalized Search Tree
     - `BITMAP` - Bitmap index
     - `COLUMNSTORE` - Columnstore index

3. **Column/Expression List**
   - Simple columns: `column_name`
   - Expression indexes (Task 17): `( expression )`
   - Expression indexes require explicit double parentheses
   - Multiple columns/expressions supported

4. **WHERE clause**
   - Creates partial/filtered index (Task 17)
   - Index only includes rows matching condition
   - Syntax: `WHERE boolean_expression`

5. **TABLESPACE**
   - Specifies tablespace for index storage
   - Phase 2 Task 2.3 feature

### Examples

```sql
-- Simple index
CREATE INDEX idx_users_email ON users(email);

-- Unique index
CREATE UNIQUE INDEX idx_users_username ON users(username);

-- Composite index
CREATE INDEX idx_orders_customer_product ON orders(customer_id, product_id);

-- Index with specific method
CREATE INDEX idx_tags USING GIN ON posts(tags);

-- Expression index (note double parentheses)
CREATE INDEX idx_users_lower_email ON users ((LOWER(email)));

-- Partial/filtered index
CREATE INDEX idx_active_users ON users(username) WHERE active = true;

-- Index with tablespace
CREATE INDEX idx_large_table ON large_table(id) TABLESPACE fast_storage;

-- Complex example with all options
CREATE UNIQUE INDEX idx_complex
    ON products USING BTREE ((UPPER(name)))
    WHERE in_stock = true
    TABLESPACE ssd_storage;
```

### Implementation Notes

- Parser location: lines 743-895
- Dispatch: parseStatement() lines 335-337
- Expression indexes use IndexColumn union type (column name or expression)
- Expression indexes must use explicit parentheses: `((expr))` not `(expr)`
- WHERE clause supports full expression parser
- Index type stored as StringId (extensible for custom index types)

## CREATE TRIGGER

**Location:** `parseCreateTrigger()` at line 1741

### Syntax (BNF)

```bnf
-- Table Trigger
CREATE TRIGGER trigger_name
    { BEFORE | AFTER }
    { INSERT | UPDATE | DELETE }
    ON table_name
    FOR ROW
    EXECUTE PROCEDURE procedure_name [ () ]

-- Database Trigger (see CREATE DATABASE TRIGGER)
```

### Options

1. **Timing**
   - `BEFORE` - Trigger executes before the event
   - `AFTER` - Trigger executes after the event

2. **Event**
   - `INSERT` - Trigger on INSERT operations
   - `UPDATE` - Trigger on UPDATE operations
   - `DELETE` - Trigger on DELETE operations

3. **Granularity**
   - `FOR ROW` - Trigger executes for each row (FOR EACH ROW)
   - Note: Parser expects `FOR ROW`, may accept `FOR EACH ROW` in future

4. **Procedure**
   - `EXECUTE PROCEDURE procedure_name` - Specifies trigger procedure
   - Optional parentheses after procedure name

### Examples

```sql
-- Insert trigger
CREATE TRIGGER trg_users_insert
    BEFORE INSERT ON users
    FOR ROW
    EXECUTE PROCEDURE validate_user();

-- Update trigger
CREATE TRIGGER trg_orders_update
    AFTER UPDATE ON orders
    FOR ROW
    EXECUTE PROCEDURE log_order_change;

-- Delete trigger
CREATE TRIGGER trg_products_delete
    BEFORE DELETE ON products
    FOR ROW
    EXECUTE PROCEDURE archive_product();
```

### Implementation Notes

- Parser location: lines 1741-1871
- Phase 2 Wave 2 - Agent C feature
- **Dispatched** in parseStatement() (lines 372-374)
- Automatically detects database triggers and delegates to parseCreateDatabaseTriggerImpl()
- FOR EACH ROW simplified to FOR ROW in current implementation

## CREATE DATABASE TRIGGER

**Location:** `parseCreateDatabaseTrigger()` and `parseCreateDatabaseTriggerImpl()` at lines 1907-2063

### Syntax (BNF)

```bnf
CREATE TRIGGER trigger_name
    [ ACTIVE | INACTIVE ]
    ON { CONNECT | DISCONNECT | TRANSACTION START | TRANSACTION COMMIT | TRANSACTION ROLLBACK }
    [ POSITION n ]
    { AS procedure_name [ () ] | EXECUTE PROCEDURE procedure_name [ () ] }
```

### Options

1. **State**
   - `ACTIVE` - Trigger is active (default)
   - `INACTIVE` - Trigger is inactive (won't execute)

2. **Database Events**
   - `ON CONNECT` - Fires when user connects to database
   - `ON DISCONNECT` - Fires when user disconnects from database
   - `ON TRANSACTION START` - Fires when transaction begins
   - `ON TRANSACTION COMMIT` - Fires when transaction commits
   - `ON TRANSACTION ROLLBACK` - Fires when transaction rolls back

3. **Position**
   - `POSITION n` - Execution order when multiple triggers on same event
   - n is integer value (0 = default)

4. **Procedure Specification**
   - `AS procedure_name` - Firebird-style syntax
   - `EXECUTE PROCEDURE procedure_name` - PostgreSQL-style syntax
   - Both forms optional parentheses after procedure name

### Examples

```sql
-- Connection trigger
CREATE TRIGGER trg_on_connect
    ACTIVE
    ON CONNECT
    POSITION 1
    AS log_connection();

-- Transaction trigger
CREATE TRIGGER trg_transaction_start
    ON TRANSACTION START
    EXECUTE PROCEDURE init_transaction_context;

-- Disconnect trigger
CREATE TRIGGER trg_cleanup
    INACTIVE
    ON DISCONNECT
    AS cleanup_session();

-- Multiple triggers with positions
CREATE TRIGGER trg_commit_first
    ON TRANSACTION COMMIT
    POSITION 1
    AS audit_commit();

CREATE TRIGGER trg_commit_second
    ON TRANSACTION COMMIT
    POSITION 2
    AS notify_commit();
```

### Implementation Notes

- Parser location: parseCreateDatabaseTriggerImpl() lines 1931-2063
- Entry point: parseCreateDatabaseTrigger() lines 1907-1929
- Firebird-style database triggers (ON CONNECT, etc.)
- Automatically detected by parseCreateTrigger() based on ACTIVE/INACTIVE/ON keywords
- Position determines execution order for multiple triggers on same event
- Both AS and EXECUTE PROCEDURE syntaxes supported

## CREATE FUNCTION

**Location:** `parseCreateFunction()` at line 2067

### Syntax (BNF)

```bnf
CREATE [ OR REPLACE ] FUNCTION function_name
    ( [ parameter_list ] )
    RETURNS return_type
    [ SQL SECURITY { DEFINER | INVOKER } ]
    AS
    psql_block

parameter_list ::=
    parameter [, ...]

parameter ::=
    parameter_name data_type [ DEFAULT expression ]
```

### Options

1. **OR REPLACE**
   - Replace existing function if it exists
   - Note: Not yet in parseStatement switch (flag parsed but not dispatched)

2. **Parameters**
   - Zero or more named parameters
   - Each parameter: `name type [ DEFAULT value ]`
   - Parameter modes (IN/OUT/INOUT) not yet in lexer - defaults to IN
   - Phase 3 Enhancement planned for full IN/OUT/INOUT support

3. **RETURNS**
   - Required return type specification
   - Any valid data type

4. **SQL SECURITY** (Phase 3.1)
   - `SQL SECURITY DEFINER` - Execute with function creator's privileges
   - `SQL SECURITY INVOKER` - Execute with caller's privileges (default)
   - Optional clause

5. **AS psql_block**
   - Function body in PSQL (Procedural SQL)
   - See PSQL Block syntax below

### PSQL Block Structure

```bnf
[ DECLARE
    variable_declaration [; ...]
]
BEGIN
    statement [; ...]
    [ EXCEPTION
        exception_handler [; ...]
    ]
END
```

### PSQL Statements

- `IF ... THEN ... ELSE ... END IF`
- `LOOP ... END LOOP`
- `WHILE ... DO ... END WHILE`
- `EXIT [ WHEN condition ]`
- `RETURN expression`
- `RAISE exception`
- Assignment: `variable := expression`
- SELECT, INSERT, UPDATE, DELETE

### Examples

```sql
-- Simple function
CREATE FUNCTION add_numbers(a INT, b INT)
RETURNS INT
AS
BEGIN
    RETURN a + b;
END;

-- Function with default parameters
CREATE FUNCTION greet(name VARCHAR(100) DEFAULT 'World')
RETURNS VARCHAR(200)
AS
BEGIN
    RETURN 'Hello, ' || name || '!';
END;

-- Function with SQL SECURITY
CREATE FUNCTION get_sensitive_data()
RETURNS TEXT
SQL SECURITY DEFINER
AS
BEGIN
    RETURN (SELECT secret FROM sensitive_table LIMIT 1);
END;

-- Function with variables and control flow
CREATE FUNCTION factorial(n INT)
RETURNS INT
AS
DECLARE
    result INT;
    i INT;
BEGIN
    result := 1;
    i := 1;

    WHILE i <= n DO
        result := result * i;
        i := i + 1;
    END WHILE;

    RETURN result;
END;

-- Function with exception handling
CREATE FUNCTION safe_divide(a DECIMAL, b DECIMAL)
RETURNS DECIMAL
AS
DECLARE
    result DECIMAL;
BEGIN
    IF b = 0 THEN
        RAISE 'Division by zero';
    END IF;

    result := a / b;
    RETURN result;
EXCEPTION
    WHEN OTHERS THEN
        RETURN NULL;
END;
```

### Implementation Notes

- Parser location: lines 2067-2149
- Phase 2 Task 10.2 - PSQL Stored Procedures and Functions
- **Dispatched** in parseStatement() (lines 376-378)
- OR REPLACE flag parsed
- Parameter mode defaults to IN (OUT/INOUT tokens not yet in lexer)
- SQL SECURITY clause optional (Phase 3.1)
- PSQL block parser: parsePSQLBlock() lines 2273+
- Parameter parser: parseParameter() lines 2240-2271


   - Zero or more named parameters
   - Each parameter: `name type [ DEFAULT value ]`

3. **SQL SECURITY** (Phase 3.1)
   - `SQL SECURITY DEFINER` - Execute with procedure creator's privileges
   - `SQL SECURITY INVOKER` - Execute with caller's privileges (default)
   - Optional clause

4. **AS psql_block**
   - Procedure body in PSQL (same structure as functions)
   - No RETURNS clause (procedures don't return values directly)

### Examples

```sql
-- Simple procedure
CREATE PROCEDURE log_event(event_name VARCHAR(100))
AS
BEGIN
    INSERT INTO event_log (event, timestamp)
    VALUES (event_name, CURRENT_TIMESTAMP);
END;

-- Procedure with multiple parameters
CREATE PROCEDURE create_user(
    username VARCHAR(50),
    email VARCHAR(100),
    initial_balance DECIMAL DEFAULT 0.0
)
AS
BEGIN
    INSERT INTO users (username, email, balance, created_at)
    VALUES (username, email, initial_balance, CURRENT_TIMESTAMP);
END;

-- Procedure with SQL SECURITY
CREATE PROCEDURE admin_cleanup()
SQL SECURITY DEFINER
AS
BEGIN
    DELETE FROM temp_data WHERE created_at < CURRENT_TIMESTAMP - INTERVAL '1 day';
END;

-- Procedure with control flow
CREATE PROCEDURE process_orders()
AS
DECLARE
    order_count INT;
BEGIN
    SELECT COUNT(*) INTO order_count FROM pending_orders;

    IF order_count > 0 THEN
        UPDATE pending_orders SET status = 'processing';
        -- Process orders...
    END IF;
END;
```

## CREATE TYPE

**Location:** `parseCreateType()` at line 4693

### Syntax (BNF)

```bnf
-- Composite Type
CREATE TYPE type_name AS (
    field_name data_type [, ...]
)

-- Enum Type
CREATE TYPE type_name AS ENUM (
    'value' [, ...]
)

-- Range Type
CREATE TYPE type_name AS RANGE (
    SUBTYPE = base_type
)
```

### Type Kinds

1. **COMPOSITE** (Row/Struct Type)
   - Contains multiple named fields
   - Each field has name and data type
   - Default if AS is followed by `(`

2. **ENUM** (Enumerated Type)
   - Contains list of string literal values
   - Values must be string literals (quoted)
   - Syntax: `AS ENUM ('value1', 'value2', ...)`

3. **RANGE** (Range Type)
   - Based on another data type (subtype)
   - Syntax: `AS RANGE ( SUBTYPE = typename )`
   - Runtime support needed for full functionality

### Examples

```sql
-- Composite type
CREATE TYPE address AS (
    street VARCHAR(100),
    city VARCHAR(50),
    state VARCHAR(2),
    zip VARCHAR(10)
);

-- Another composite type
CREATE TYPE person AS (
    name VARCHAR(100),
    age INT,
    email VARCHAR(100)
);

-- Enum type
CREATE TYPE status AS ENUM (
    'pending',
    'active',
    'completed',
    'cancelled'
);

CREATE TYPE day_of_week AS ENUM (
    'Monday',
    'Tuesday',
    'Wednesday',
    'Thursday',
    'Friday',
    'Saturday',
    'Sunday'
);

-- Range type
CREATE TYPE int_range AS RANGE (
    SUBTYPE = INT
);

CREATE TYPE timestamp_range AS RANGE (
    SUBTYPE = TIMESTAMP
);

-- Usage in tables
CREATE TABLE users (
    id INT PRIMARY KEY,
    home_address address,
    status status
);
```

### Implementation Notes

- Parser location: lines 4693-4826

## CREATE DOMAIN

**Location:** `parseCreateDomain()` at line 4828

### Syntax (BNF)

```bnf
CREATE DOMAIN domain_name AS data_type
    [ DEFAULT expression ]
    [ NOT NULL ]
    [ CHECK ( condition ) ]
```

### Options

1. **Base Type**
   - Any valid data type
   - Required after AS keyword

2. **DEFAULT**
   - Default value for domain
   - Optional expression

3. **NOT NULL**
   - Domain does not accept NULL values
   - Optional constraint

4. **CHECK**
   - CHECK constraint on domain values
   - Syntax: `CHECK ( boolean_expression )`
   - Optional constraint

### Examples

```sql
-- Simple domain
CREATE DOMAIN email AS VARCHAR(100);

-- Domain with constraint
CREATE DOMAIN positive_int AS INT
    CHECK (VALUE > 0);

-- Domain with default
CREATE DOMAIN status_flag AS VARCHAR(10)
    DEFAULT 'active';

-- Domain with multiple constraints
CREATE DOMAIN us_zipcode AS VARCHAR(10)
    NOT NULL
    CHECK (VALUE ~ '^\d{5}(-\d{4})?$');

-- Domain with all options
CREATE DOMAIN age_years AS INT
    DEFAULT 0
    NOT NULL
    CHECK (VALUE >= 0 AND VALUE <= 150);

-- Currency domain
CREATE DOMAIN currency_amount AS DECIMAL(10,2)
    NOT NULL
    DEFAULT 0.00
    CHECK (VALUE >= 0);

-- Usage in tables
CREATE TABLE products (
    id INT PRIMARY KEY,
    price currency_amount,
    contact_email email
);
```

### Implementation Notes

- Parser location: lines 4828-4905
- Domain Types feature
- Domains are constrained types (base type + constraints)
- CHECK expression can reference VALUE keyword
- All options (DEFAULT, NOT NULL, CHECK) are optional
- Multiple CHECK constraints not supported (single CHECK only)
- isIdentifierOrUnreservedKeyword() helper allows keywords as domain names

## CREATE TABLESPACE

**Location:** `parseCreateTablespace()` at line 5540

### Syntax (BNF)

```bnf
CREATE TABLESPACE tablespace_name
    LOCATION 'path'
    [ AUTOEXTEND { ON | OFF } ]
    [ AUTOEXTEND_SIZE n ]
    [ MAXSIZE { n | UNLIMITED } ]
    [ PREALLOC n ]
```

### Options

1. **LOCATION**
   - Required file system path for tablespace
   - Must be string literal

2. **AUTOEXTEND**
   - `ON` - Tablespace automatically extends when full (default)
   - `OFF` - Tablespace does not automatically extend

3. **AUTOEXTEND_SIZE**
   - Size to extend by (in MB)
   - Default: 100 MB
   - Integer value

4. **MAXSIZE**
   - Maximum size limit
   - `UNLIMITED` - No size limit (default, stored as 0)
   - Integer value in MB

5. **PREALLOC**
   - Number of pages to pre-allocate
   - Default: 0 (no pre-allocation)
   - Integer value

### Examples

```sql
-- Basic tablespace
CREATE TABLESPACE fast_storage
    LOCATION '/mnt/ssd/data';

-- Tablespace with size limits
CREATE TABLESPACE limited_space
    LOCATION '/mnt/disk/data'
    MAXSIZE 10240;  -- 10 GB

-- Tablespace without auto-extend
CREATE TABLESPACE fixed_size
    LOCATION '/mnt/disk/fixed'
    AUTOEXTEND OFF;

-- Tablespace with custom extend size
CREATE TABLESPACE incremental
    LOCATION '/mnt/disk/data'
    AUTOEXTEND ON
    AUTOEXTEND_SIZE 256  -- Extend by 256 MB at a time
    MAXSIZE UNLIMITED;

-- Tablespace with pre-allocation
CREATE TABLESPACE preallocated
    LOCATION '/mnt/ssd/data'
    PREALLOC 1000  -- Pre-allocate 1000 pages
    AUTOEXTEND_SIZE 128
    MAXSIZE 5120;  -- 5 GB max

-- Complete example
CREATE TABLESPACE production_data
    LOCATION '/data/production'
    AUTOEXTEND ON
    AUTOEXTEND_SIZE 512
    MAXSIZE 102400  -- 100 GB
    PREALLOC 500;
```

### Implementation Notes

- Parser location: lines 5540-5652
- Phase 2 Task 2.3 feature
- All size values in MB (megabytes)
- MAXSIZE 0 means UNLIMITED
- Default values:
  - AUTOEXTEND: ON (true)
  - AUTOEXTEND_SIZE: 100 MB
  - MAXSIZE: UNLIMITED (0)
  - PREALLOC: 0 pages
- LOCATION must be string literal (file path)

## CREATE SEQUENCE

**Location:** `parseCreateSequence()` at line 5793

### Syntax (BNF)

```bnf
CREATE SEQUENCE sequence_name
    [ INCREMENT BY increment ]
    [ MINVALUE minvalue | NO MINVALUE ]
    [ MAXVALUE maxvalue | NO MAXVALUE ]
    [ START WITH start ]
    [ CACHE cache ]
    [ CYCLE | NO CYCLE ]
```

### Options

1. **INCREMENT BY**
   - Step size for sequence
   - Positive or negative integer
   - Default: 1

2. **MINVALUE / NO MINVALUE**
   - Minimum value for sequence
   - `MINVALUE n` - Explicit minimum
   - `NO MINVALUE` - Use default minimum

3. **MAXVALUE / NO MAXVALUE**
   - Maximum value for sequence
   - `MAXVALUE n` - Explicit maximum
   - `NO MAXVALUE` - Use default maximum

4. **START WITH**
   - Starting value for sequence
   - Integer expression

5. **CACHE**
   - Number of sequence values to cache

## CREATE POLICY

**Location:** `parseCreatePolicy()` at line 9364

### Syntax (BNF)

```bnf
CREATE POLICY policy_name ON table_name
    [ FOR { ALL | SELECT | INSERT | UPDATE | DELETE } ]
    [ TO { role_name [, ...] | PUBLIC } ]
    [ USING ( expression ) ]
    [ WITH CHECK ( expression ) ]
```

### Options

1. **FOR command**
   - Specifies which operations policy applies to
   - `ALL` - All operations (default)
   - `SELECT` - SELECT operations only
   - `INSERT` - INSERT operations only
   - `UPDATE` - UPDATE operations only
   - `DELETE` - DELETE operations only

2. **TO roles**
   - Specifies which roles policy applies to
   - `PUBLIC` - All roles (empty role list)
   - Comma-separated list of role names
   - Default: all roles if omitted

3. **USING ( expression )**
   - Row-level filter for SELECT/UPDATE/DELETE
   - Boolean expression evaluated for each row
   - Rows where expression is false are invisible/inaccessible
   - Optional clause

4. **WITH CHECK ( expression )**
   - Row-level check for INSERT/UPDATE
   - Boolean expression evaluated for new/modified rows
   - Rows failing check are rejected
   - Optional clause

### Examples

```sql
-- Policy for all users to see only their own rows
CREATE POLICY user_isolation ON user_data
    FOR ALL
    TO PUBLIC
    USING (user_id = current_user_id());

-- SELECT-only policy
CREATE POLICY view_active_records ON records
    FOR SELECT
    USING (status = 'active');

-- Policy for specific role
CREATE POLICY admin_full_access ON sensitive_table
    FOR ALL
    TO admin
    USING (true);

-- INSERT policy with check
CREATE POLICY valid_new_orders ON orders
    FOR INSERT
    WITH CHECK (total > 0 AND customer_id IS NOT NULL);

-- UPDATE policy with both USING and WITH CHECK
CREATE POLICY update_own_posts ON posts
    FOR UPDATE
    TO editors
    USING (author_id = current_user_id())
    WITH CHECK (status != 'archived');

-- Policy for multiple roles
CREATE POLICY manager_access ON employee_records
    FOR ALL
    TO managers, hr_staff, executives
    USING (department_id IN (SELECT dept_id FROM user_departments WHERE user_id = current_user_id()));

-- DELETE policy
CREATE POLICY safe_delete ON important_data
    FOR DELETE
    USING (can_delete = true AND created_at < CURRENT_DATE - INTERVAL '1 year');

-- Complete example
CREATE POLICY tenant_isolation ON tenant_data
    FOR ALL
    TO tenant_users
    USING (tenant_id = current_tenant_id())
    WITH CHECK (tenant_id = current_tenant_id());
```

- Parser location: lines 9364-9513
- Security Phase 3.4 - Row-Level Security
- PolicyCommand enum: ALL, SELECT, INSERT, UPDATE, DELETE_CMD
- Empty roles vector means PUBLIC (all roles)
- USING expression for row visibility

## Constraint Reference

### Column-Level Constraints

1. **NOT NULL**
   ```sql
   column_name data_type NOT NULL
   ```
   - Prevents NULL values in column

2. **NULL**
   ```sql
   column_name data_type NULL
   ```
   - Explicitly allows NULL values (default)

3. **DEFAULT**
   ```sql
   column_name data_type DEFAULT expression
   ```
   - Provides default value for column
   - Expression evaluated at insert time

4. **PRIMARY KEY**
   ```sql
   column_name data_type PRIMARY KEY
   ```
   - Designates column as primary key
   - Implies NOT NULL and UNIQUE
   - Only one per table

5. **UNIQUE**
   ```sql
   column_name data_type UNIQUE
   ```
   - Ensures column values are unique

6. **CHECK**
   ```sql
   column_name data_type CHECK ( condition )
   ```
   - Validates column values against condition

7. **REFERENCES (Foreign Key)**
   ```sql
   column_name data_type REFERENCES table_name [ ( column_name ) ]
       [ ON DELETE action ]
       [ ON UPDATE action ]
   ```
   - Foreign key actions:
     - CASCADE
     - RESTRICT
     - SET NULL
     - SET DEFAULT
     - NO ACTION

8. **GENERATED AS IDENTITY**
   ```sql
   column_name data_type GENERATED { ALWAYS | BY DEFAULT } AS IDENTITY
   ```
   - Auto-increment column
   - ALWAYS: No manual values allowed
   - BY DEFAULT: Manual values allowed

9. **GENERATED AS (expression)**
   ```sql
   column_name data_type GENERATED ALWAYS AS ( expression ) [ STORED | VIRTUAL ]
   ```
   - Computed column
   - STORED: Value physically stored
   - VIRTUAL: Value computed on access

### Table-Level Constraints

1. **PRIMARY KEY**
   ```sql
   [ CONSTRAINT name ] PRIMARY KEY ( column [, ...] )
   ```
   - Composite primary key

2. **UNIQUE**
   ```sql
   [ CONSTRAINT name ] UNIQUE ( column [, ...] )
   ```
   - Composite unique constraint

3. **FOREIGN KEY**
   ```sql
   [ CONSTRAINT name ] FOREIGN KEY ( column [, ...] )
       REFERENCES table_name ( column [, ...] )
       [ ON DELETE action ]
       [ ON UPDATE action ]
       [ [ NOT ] DEFERRABLE ]
       [ INITIALLY { DEFERRED | IMMEDIATE } ]
   ```
   - Composite foreign key
   - Deferred checking supported

4. **CHECK**
   ```sql
   [ CONSTRAINT name ] CHECK ( expression )
   ```
   - Table-level CHECK constraint

### Constraint Examples

```sql
-- All column constraints
CREATE TABLE demo (
    id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    code VARCHAR(10) NOT NULL UNIQUE,
    status VARCHAR(20) DEFAULT 'pending',
    amount DECIMAL(10,2) CHECK (amount > 0),
    parent_id INT REFERENCES demo(id) ON DELETE CASCADE,
    computed INT GENERATED ALWAYS AS (id * 2) STORED
);

-- All table constraints
CREATE TABLE orders (
    order_id INT,
    customer_id INT,
    product_id INT,
    quantity INT,
    total DECIMAL(10,2),

    CONSTRAINT pk_orders PRIMARY KEY (order_id),
    CONSTRAINT uk_customer_product UNIQUE (customer_id, product_id),
    CONSTRAINT fk_customer FOREIGN KEY (customer_id)
        REFERENCES customers(id)
        ON DELETE RESTRICT
        DEFERRABLE INITIALLY DEFERRED,
    CONSTRAINT fk_product FOREIGN KEY (product_id)
        REFERENCES products(id)
        ON UPDATE CASCADE,
    CONSTRAINT chk_positive CHECK (quantity > 0 AND total > 0)
);
```

### Foreign Key Actions

| Action | Description |
|--------|-------------|
| CASCADE | Delete/update child rows when parent changes |
| RESTRICT | Prevent parent change if children exist |
| SET NULL | Set child column to NULL when parent changes |
| SET DEFAULT | Set child column to default when parent changes |
| NO ACTION | Same as RESTRICT (no action on parent change) |

### Deferred Constraints

- **DEFERRABLE** - Constraint can be deferred until transaction end
- **NOT DEFERRABLE** - Constraint checked immediately (default)
- **INITIALLY DEFERRED** - Start transaction with constraint deferred
- **INITIALLY IMMEDIATE** - Start transaction with constraint immediate (default)

```sql
-- Deferred constraint example
CREATE TABLE parent (
    id INT PRIMARY KEY
);

CREATE TABLE child (
    id INT PRIMARY KEY,
    parent_id INT,
    CONSTRAINT fk_parent FOREIGN KEY (parent_id)
        REFERENCES parent(id)
        DEFERRABLE INITIALLY DEFERRED
);

-- Allows circular references within transaction
BEGIN;
INSERT INTO child VALUES (1, 1);
INSERT INTO parent VALUES (1);
COMMIT;  -- Constraint checked here
```
