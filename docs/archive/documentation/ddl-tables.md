### DDL: Tables

**What it is**

Table DDL (Data Definition Language) provides the foundation for database schema design. Tables define the structure for storing data, including columns with specific data types, constraints for data integrity, indexes for performance, and relationships between entities. ScratchBird implements comprehensive table DDL supporting creation, alteration, and deletion with advanced features like identity columns, computed columns, and complex constraints.

**Why it matters**

- **Data Integrity**: Constraints ensure data validity and prevent corruption
- **Performance**: Proper table design with appropriate indexes enables efficient queries
- **Relationships**: Foreign keys maintain referential integrity across tables
- **Evolution**: ALTER operations allow schema changes without data loss
- **Standards**: Following SQL standards ensures portability and maintainability

**How to use it**

Design tables thoughtfully with appropriate data types and constraints. Use ALTER TABLE for schema evolution, implement proper foreign key relationships, and consider performance implications of indexes and constraints.

## CREATE TABLE

### Basic Syntax

```sql
CREATE TABLE [IF NOT EXISTS] table_name (
    column_definitions,
    table_constraints
) [table_options];
```

### Column Definitions

Each column definition (`src/engine/parser_ddl.cpp`) can include:

```sql
column_name data_type [column_constraints]
```

### Simple Table Creation

```sql
-- Basic table
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Table with multiple constraints
CREATE TABLE products (
    id BIGINT PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    price DECIMAL(10,2) NOT NULL CHECK (price > 0),
    category_id INTEGER NOT NULL,
    in_stock BOOLEAN DEFAULT TRUE,
    CONSTRAINT fk_category 
        FOREIGN KEY (category_id) REFERENCES categories(id)
);
```

## Column Constraints

### NOT NULL Constraint

```sql
CREATE TABLE employees (
    id INTEGER PRIMARY KEY,
    -- Required fields
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    -- Optional fields
    middle_name VARCHAR(50),  -- Can be NULL
    phone VARCHAR(20)
);
```

### DEFAULT Values

```sql
CREATE TABLE audit_log (
    id BIGINT PRIMARY KEY,
    action VARCHAR(50) NOT NULL,
    -- Literal defaults
    status VARCHAR(20) DEFAULT 'pending',
    retry_count INTEGER DEFAULT 0,
    -- Function defaults
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    expires_at TIMESTAMP DEFAULT (CURRENT_TIMESTAMP + INTERVAL '30 days'),
    -- Expression defaults
    priority INTEGER DEFAULT (CASE 
        WHEN action = 'ERROR' THEN 1 
        ELSE 5 
    END)
);
```

### CHECK Constraints

```sql
CREATE TABLE orders (
    id BIGINT PRIMARY KEY,
    -- Column-level CHECK
    quantity INTEGER CHECK (quantity > 0),
    unit_price DECIMAL(10,2) CHECK (unit_price >= 0),
    discount_percent INTEGER CHECK (discount_percent BETWEEN 0 AND 100),
    -- Complex CHECK with multiple columns (table-level)
    total_price DECIMAL(10,2),
    CONSTRAINT chk_total CHECK (
        total_price = quantity * unit_price * (1 - discount_percent / 100.0)
    )
);
```

### UNIQUE Constraints

```sql
CREATE TABLE accounts (
    id INTEGER PRIMARY KEY,
    -- Column-level UNIQUE
    account_number VARCHAR(20) UNIQUE,
    email VARCHAR(100) UNIQUE NOT NULL,
    -- Composite UNIQUE (table-level)
    branch_code VARCHAR(10),
    local_account_id INTEGER,
    CONSTRAINT uk_branch_account UNIQUE (branch_code, local_account_id)
);
```

## Identity Columns

ScratchBird supports SQL standard identity columns (`include/scratchbird/engine/ast.h`):

### GENERATED ALWAYS AS IDENTITY

```sql
CREATE TABLE invoices (
    -- Always generated, cannot override
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    invoice_number VARCHAR(50) NOT NULL,
    amount DECIMAL(12,2)
);

-- INSERT without specifying id
INSERT INTO invoices (invoice_number, amount) 
VALUES ('INV-001', 1500.00);

-- Cannot override identity value
-- This would fail:
-- INSERT INTO invoices (id, invoice_number, amount) 
-- VALUES (100, 'INV-002', 2000.00);  -- ERROR
```

### GENERATED BY DEFAULT AS IDENTITY

```sql
CREATE TABLE customers (
    -- Can be overridden if explicitly provided
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE
);

-- Auto-generated ID
INSERT INTO customers (name, email) 
VALUES ('John Doe', 'john@example.com');

-- Override with explicit value
INSERT INTO customers (id, name, email) 
VALUES (1000, 'Jane Smith', 'jane@example.com');
```

### Identity Options

```sql
CREATE TABLE sequences_example (
    id BIGINT GENERATED ALWAYS AS IDENTITY (
        START WITH 1000
        INCREMENT BY 10
        MINVALUE 1000
        MAXVALUE 999999
        CYCLE
    ) PRIMARY KEY,
    data VARCHAR(100)
);
```

## Computed Columns

Computed (generated) columns derive values from expressions:

```sql
CREATE TABLE rectangles (
    id INTEGER PRIMARY KEY,
    width DECIMAL(10,2) NOT NULL,
    height DECIMAL(10,2) NOT NULL,
    -- Computed column
    area DECIMAL(10,2) COMPUTED BY (width * height),
    perimeter DECIMAL(10,2) COMPUTED BY (2 * (width + height))
);

-- Computed columns with functions
CREATE TABLE employees (
    id INTEGER PRIMARY KEY,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    full_name VARCHAR(101) COMPUTED BY (first_name || ' ' || last_name),
    name_length INTEGER COMPUTED BY (CHAR_LENGTH(first_name) + CHAR_LENGTH(last_name))
);
```

## Character Set and Collation

Text columns can specify character sets and collations:

```sql
CREATE TABLE international_data (
    id INTEGER PRIMARY KEY,
    -- UTF-8 with case-insensitive collation
    name VARCHAR(100) CHARACTER SET UTF8 COLLATE unicode_ci,
    -- Binary comparison
    code VARCHAR(20) CHARACTER SET ASCII COLLATE binary,
    -- Language-specific collation
    description TEXT CHARACTER SET UTF8 COLLATE en_US,
    -- Default charset/collation
    notes TEXT
);
```

## Table Constraints

### PRIMARY KEY

```sql
-- Single column primary key
CREATE TABLE departments (
    id INTEGER PRIMARY KEY,
    name VARCHAR(100) NOT NULL
);

-- Composite primary key
CREATE TABLE order_items (
    order_id INTEGER,
    product_id INTEGER,
    quantity INTEGER NOT NULL,
    price DECIMAL(10,2) NOT NULL,
    PRIMARY KEY (order_id, product_id)
);

-- Named primary key constraint
CREATE TABLE regions (
    region_code VARCHAR(10),
    region_name VARCHAR(100),
    CONSTRAINT pk_regions PRIMARY KEY (region_code)
);
```

### FOREIGN KEY

```sql
-- Basic foreign key
CREATE TABLE orders (
    id INTEGER PRIMARY KEY,
    customer_id INTEGER NOT NULL,
    FOREIGN KEY (customer_id) REFERENCES customers(id)
);

-- Foreign key with actions
CREATE TABLE order_items (
    id INTEGER PRIMARY KEY,
    order_id INTEGER NOT NULL,
    product_id INTEGER NOT NULL,
    CONSTRAINT fk_order 
        FOREIGN KEY (order_id) 
        REFERENCES orders(id) 
        ON DELETE CASCADE 
        ON UPDATE CASCADE,
    CONSTRAINT fk_product 
        FOREIGN KEY (product_id) 
        REFERENCES products(id)
        ON DELETE RESTRICT
        ON UPDATE CASCADE
);

-- Self-referencing foreign key
CREATE TABLE employees (
    id INTEGER PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    manager_id INTEGER,
    CONSTRAINT fk_manager 
        FOREIGN KEY (manager_id) 
        REFERENCES employees(id)
        ON DELETE SET NULL
);

-- Composite foreign key
CREATE TABLE city_districts (
    country_code VARCHAR(2),
    city_id INTEGER,
    district_id INTEGER,
    district_name VARCHAR(100),
    PRIMARY KEY (country_code, city_id, district_id),
    CONSTRAINT fk_city
        FOREIGN KEY (country_code, city_id)
        REFERENCES cities(country_code, id)
);
```

### Deferrable Constraints

```sql
CREATE TABLE transactions (
    id INTEGER PRIMARY KEY,
    account_id INTEGER NOT NULL,
    amount DECIMAL(12,2) NOT NULL,
    balance_after DECIMAL(12,2),
    -- Deferrable constraint checked at commit
    CONSTRAINT fk_account
        FOREIGN KEY (account_id)
        REFERENCES accounts(id)
        DEFERRABLE INITIALLY DEFERRED,
    -- Immediate check (default)
    CONSTRAINT chk_balance
        CHECK (balance_after >= 0)
        DEFERRABLE INITIALLY IMMEDIATE
);
```

## External Files

Tables can be stored in external files:

```sql
CREATE TABLE external_data (
    id INTEGER PRIMARY KEY,
    data BLOB
) EXTERNAL FILE '/path/to/data/file.dat';
```

## ALTER TABLE

ALTER TABLE modifies existing table structure (`src/engine/parser_ddl.cpp`):

### ADD COLUMN

```sql
-- Basic column addition
ALTER TABLE users ADD COLUMN phone VARCHAR(20);

-- With constraints and defaults
ALTER TABLE products 
ADD COLUMN discount_percent INTEGER DEFAULT 0 
    CHECK (discount_percent BETWEEN 0 AND 100) NOT NULL;

-- Multiple columns
ALTER TABLE orders
ADD COLUMN shipping_address TEXT,
ADD COLUMN billing_address TEXT,
ADD COLUMN notes VARCHAR(500);
```

### ALTER COLUMN

```sql
-- Change data type
ALTER TABLE products ALTER COLUMN price TYPE DECIMAL(12,2);

-- Add/remove NOT NULL
ALTER TABLE users ALTER COLUMN email SET NOT NULL;
ALTER TABLE users ALTER COLUMN phone DROP NOT NULL;

-- Set/drop DEFAULT
ALTER TABLE orders ALTER COLUMN status SET DEFAULT 'pending';
ALTER TABLE orders ALTER COLUMN priority DROP DEFAULT;

-- Multiple alterations
ALTER TABLE employees
ALTER COLUMN salary TYPE DECIMAL(12,2),
ALTER COLUMN hire_date SET NOT NULL,
ALTER COLUMN department_id SET DEFAULT 1;
```

### DROP COLUMN

```sql
-- Single column
ALTER TABLE users DROP COLUMN middle_name;

-- Multiple columns
ALTER TABLE products
DROP COLUMN deprecated_field1,
DROP COLUMN deprecated_field2;

-- CASCADE dependencies (if supported)
ALTER TABLE orders DROP COLUMN customer_id CASCADE;
```

### ADD CONSTRAINT

```sql
-- Add PRIMARY KEY
ALTER TABLE legacy_table 
ADD CONSTRAINT pk_legacy PRIMARY KEY (id);

-- Add UNIQUE constraint
ALTER TABLE users 
ADD CONSTRAINT uk_email UNIQUE (email);

-- Add CHECK constraint
ALTER TABLE products 
ADD CONSTRAINT chk_price CHECK (price > cost);

-- Add FOREIGN KEY
ALTER TABLE orders 
ADD CONSTRAINT fk_customer 
    FOREIGN KEY (customer_id) 
    REFERENCES customers(id)
    ON DELETE CASCADE
    DEFERRABLE INITIALLY DEFERRED;

-- Multiple constraints
ALTER TABLE order_items
ADD CONSTRAINT uk_order_product UNIQUE (order_id, product_id),
ADD CONSTRAINT chk_quantity CHECK (quantity > 0),
ADD CONSTRAINT fk_order FOREIGN KEY (order_id) REFERENCES orders(id);
```

### DROP CONSTRAINT

```sql
-- Drop by name
ALTER TABLE users DROP CONSTRAINT uk_email;

-- Drop multiple constraints
ALTER TABLE orders
DROP CONSTRAINT fk_customer,
DROP CONSTRAINT chk_status;
```

## DROP TABLE

```sql
-- Basic drop
DROP TABLE temp_data;

-- Drop if exists
DROP TABLE IF EXISTS obsolete_table;

-- CASCADE dependencies
DROP TABLE parent_table CASCADE;

-- RESTRICT (default - fail if dependencies exist)
DROP TABLE important_table RESTRICT;
```

## RECREATE TABLE

RECREATE is shorthand for DROP IF EXISTS followed by CREATE:

```sql
-- Recreate with new structure
RECREATE TABLE user_sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id INTEGER NOT NULL,
    token VARCHAR(255) UNIQUE NOT NULL,
    expires_at TIMESTAMP NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_user FOREIGN KEY (user_id) REFERENCES users(id)
);
```

## Complex Table Examples

### E-commerce Schema

```sql
-- Categories with hierarchy
CREATE TABLE categories (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    parent_id INTEGER,
    path VARCHAR(500) COMPUTED BY (
        -- Materialized path for hierarchy
        COALESCE(
            (SELECT path FROM categories WHERE id = parent_id) || '/' || name,
            name
        )
    ),
    CONSTRAINT fk_parent 
        FOREIGN KEY (parent_id) REFERENCES categories(id),
    CONSTRAINT chk_no_self_parent CHECK (id != parent_id)
);

-- Products with full constraints
CREATE TABLE products (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    sku VARCHAR(50) UNIQUE NOT NULL,
    name VARCHAR(200) NOT NULL,
    description TEXT,
    category_id INTEGER NOT NULL,
    price DECIMAL(10,2) NOT NULL CHECK (price > 0),
    cost DECIMAL(10,2) CHECK (cost >= 0),
    margin DECIMAL(5,2) COMPUTED BY ((price - cost) / price * 100),
    stock_quantity INTEGER DEFAULT 0 CHECK (stock_quantity >= 0),
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_category 
        FOREIGN KEY (category_id) REFERENCES categories(id),
    CONSTRAINT chk_price_cost CHECK (price > cost)
);

-- Orders with status workflow
CREATE TABLE orders (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    order_number VARCHAR(20) UNIQUE NOT NULL,
    customer_id INTEGER NOT NULL,
    status VARCHAR(20) DEFAULT 'pending' NOT NULL,
    total_amount DECIMAL(12,2) NOT NULL CHECK (total_amount >= 0),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_customer 
        FOREIGN KEY (customer_id) REFERENCES customers(id),
    CONSTRAINT chk_status CHECK (
        status IN ('pending', 'processing', 'shipped', 'delivered', 'cancelled')
    )
);
```

### Audit and Versioning

```sql
-- Versioned table with audit
CREATE TABLE documents (
    id INTEGER NOT NULL,
    version INTEGER NOT NULL DEFAULT 1,
    title VARCHAR(200) NOT NULL,
    content TEXT,
    author_id INTEGER NOT NULL,
    is_current BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    created_by INTEGER NOT NULL,
    PRIMARY KEY (id, version),
    CONSTRAINT fk_author FOREIGN KEY (author_id) REFERENCES users(id),
    CONSTRAINT fk_creator FOREIGN KEY (created_by) REFERENCES users(id),
    -- Only one current version per document
    CONSTRAINT uk_current UNIQUE (id, is_current) WHERE is_current = TRUE
);
```

## Schema Evolution Patterns

### Adding Features

```sql
-- Start simple
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    email VARCHAR(100) NOT NULL
);

-- Add authentication
ALTER TABLE users
ADD COLUMN password_hash VARCHAR(255),
ADD COLUMN salt VARCHAR(32),
ADD COLUMN last_login TIMESTAMP;

-- Add profile
ALTER TABLE users
ADD COLUMN first_name VARCHAR(50),
ADD COLUMN last_name VARCHAR(50),
ADD COLUMN avatar_url VARCHAR(500);

-- Add constraints as data improves
ALTER TABLE users
ADD CONSTRAINT uk_email UNIQUE (email),
ALTER COLUMN password_hash SET NOT NULL;
```

### Refactoring

```sql
-- Split table
CREATE TABLE user_profiles AS
SELECT id as user_id, first_name, last_name, avatar_url
FROM users;

ALTER TABLE user_profiles
ADD PRIMARY KEY (user_id),
ADD CONSTRAINT fk_user FOREIGN KEY (user_id) REFERENCES users(id);

ALTER TABLE users
DROP COLUMN first_name,
DROP COLUMN last_name,
DROP COLUMN avatar_url;
```

## Implementation Details

**Parser Implementation** (`src/engine/parser_ddl.cpp`):
- `parse_ddl_table`: Main table DDL parser
- Column definition parsing with constraints
- Table constraint parsing
- ALTER operation classification

**AST Structure** (`include/scratchbird/engine/ast.h`):
```cpp
struct CreateTableAst {
    std::string name;
    std::string columns_raw;      // Raw column definitions
    std::string constraints_raw;  // Table constraints
    std::vector<AlterOp> alter_ops;  // For ALTER TABLE
    // Identity options
    bool identity_always;
    bool identity_by_default;
    // Additional attributes
    std::string external_file;
};
```

**Constraint Handling**:
- PRIMARY KEY: Single or composite
- FOREIGN KEY: With ON DELETE/UPDATE actions
- CHECK: Expression-based validation
- UNIQUE: Single or composite uniqueness
- DEFERRABLE: Transaction-scoped checking

**Code Anchors**:
- Table parser: `src/engine/parser_ddl.cpp` (parse_ddl_table)
- AST definitions: `include/scratchbird/engine/ast.h` (CreateTableAst)
- Constraint parsing: Split at top-level commas with parenthesis tracking
