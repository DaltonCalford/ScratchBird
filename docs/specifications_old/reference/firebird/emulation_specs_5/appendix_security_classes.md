# Appendix: Firebird 5 Security Classes and Privileges (Authoritative)

This appendix defines the ACL byte layouts and the exact security class generation order for system objects. It is authoritative for `RDB$SECURITY_CLASSES` and `RDB$USER_PRIVILEGES` bootstrap rows.

## ACL Constants (Authoritative)
- `ACL_version = 2`
- `ACL_id_list = 1`
- `ACL_priv_list = 2`
- `ACL_end = 0`
- `id_person = 3`
- `priv_control = 1`
- `priv_alter = 6`
- `priv_drop = 3`
- `priv_select = 4`
- `priv_insert = 7`
- `priv_update = 9`
- `priv_delete = 8`
- `priv_execute = 11`
- `priv_usage = 12`

## ACL Blob Templates (Authoritative)
All ACL blobs are stored in `RDB$SECURITY_CLASSES.RDB$ACL` as raw binary. The templates below use these tokens:
- `<OWNER_LEN>` = 1-byte length of `<DB_OWNER>` in bytes.
- `<OWNER_BYTES>` = ASCII bytes of `<DB_OWNER>` (uppercased user name).

### RELATION_ACL (Relation and Default Class)
Used for `SQL$<n>` and `SQL$DEFAULT<n>` created by `RelationSecurity`. Grants FULL relation privileges to owner and SELECT to PUBLIC.

```text
02 01 03 <OWNER_LEN> <OWNER_BYTES> 00 02 01 06 03 04 07 09 08 00 01 00 02 04 00 00
```

### NONREL_USAGE_ACL (Non-relation objects)
Used for fields, charsets, collations, generators, and schemas created by `NonRelationSecurity` (package=false). Grants CONTROL/ALTER/DROP/USAGE to owner and USAGE to PUBLIC.

```text
02 01 03 <OWNER_LEN> <OWNER_BYTES> 00 02 01 06 03 0C 00 01 00 02 0C 00 00
```

### NONREL_EXEC_ACL (Packages)
Used for packages created by `NonRelationSecurity` (package=true). Grants CONTROL/ALTER/DROP/EXECUTE to owner and EXECUTE to PUBLIC.

```text
02 01 03 <OWNER_LEN> <OWNER_BYTES> 00 02 01 06 03 0B 00 01 00 02 0B 00 00
```

### ROLE_ACL (Admin Role)
Used for `RDB$ADMIN` security class created by `RoleSecurity`. Grants CONTROL/ALTER/DROP/USAGE to owner. No PUBLIC list.

```text
02 01 03 <OWNER_LEN> <OWNER_BYTES> 00 02 01 06 03 0C 00 00
```

### DDL_ACL (DDL Security Classes and Database Class)
Used for DDL security classes created by `DdlSecurity` and the database security class set in `RDB$DATABASE`. Grants CONTROL/ALTER/DROP to owner. No PUBLIC list.

```text
02 01 03 <OWNER_LEN> <OWNER_BYTES> 00 02 01 06 03 00 00
```

## DDL Security Class Names (Authoritative)
DDL security class names use `SQL$D%02d%s` where `%02d` is the DDL object type and `%s` is schema suffix (empty, PUBLIC, or SYSTEM).
Creation order for DDL security classes is: iterate object types from 22 to 39 inclusive, and for each object where `isDdlObject(objectType)` is true, insert PUBLIC then SYSTEM classes if `useSchema=true`, otherwise insert the no-schema class. All DDL classes are inserted **after** the `RDB$ADMIN` SQL$ class and **before** the final database SQL$ class.
