## Overview

Tables are the fundamental data storage structures in ScratchBird, organizing data into rows and columns with strict schema definitions. ScratchBird's table implementation extends standard SQL functionality with hierarchical schema support, advanced constraint options, and enhanced storage features.

### Key Features and Capabilities

- **Hierarchical Schema Support**: Full support for 3-level qualified names (`schema.subschema.table`)
- **Advanced Constraints**: CHECK, FOREIGN KEY, UNIQUE, PRIMARY KEY with enhanced options
- **Global Temporary Tables**: Session-scoped and transaction-scoped temporary storage
- **Schema-Aware Operations**: Integration with hierarchical schema system
- **Enhanced Storage**: Optimized page structures and compression support

### ScratchBird-Specific Enhancements

1. **Schema Qualification**: Tables can be created in hierarchical schemas up to 11 levels deep
2. **Database Link Integration**: Tables can reference objects via database links (`table@link_name`)
3. **Enhanced DDL Options**: `IF NOT EXISTS` and conditional DDL operations
4. **Advanced Statistics**: Integration with enhanced optimizer cost models

## DDL Syntax Reference

### CREATE TABLE

Creates a new persistent table with specified columns, constraints, and storage options.

#### **Basic Syntax**
```sql
CREATE [GLOBAL TEMPORARY] TABLE [IF NOT EXISTS] [schema_path.]table_name
(
    column_definition [, column_definition] ...
    [, table_constraint [, table_constraint] ...]
)
[ON COMMIT {DELETE | PRESERVE} ROWS]
```

#### **Complete Syntax**
```sql
CREATE [GLOBAL TEMPORARY] TABLE [IF NOT EXISTS] qualified_table_name
(
    column_name data_type
        [DEFAULT {literal | NULL | context_variable}]
        [GENERATED {ALWAYS | BY DEFAULT} AS IDENTITY 
            [(START WITH start_value) 
             (INCREMENT BY increment_value)
             (GENERATOR uuid_generator_call)]]
        [NOT NULL] 
        [UNIQUE]
        [PRIMARY KEY]
        [CHECK (condition)]
        [REFERENCES table_name [(column_name)] [ON DELETE {CASCADE | SET NULL | SET DEFAULT | NO ACTION}] [ON UPDATE {CASCADE | SET NULL | SET DEFAULT | NO ACTION}]]
        [COLLATE collation_name]
    [, ...]
    [, [CONSTRAINT constraint_name] PRIMARY KEY (column_list)]
    [, [CONSTRAINT constraint_name] UNIQUE (column_list)]
    [, [CONSTRAINT constraint_name] FOREIGN KEY (column_list) 
        REFERENCES table_name [(column_list)]
        [ON DELETE {CASCADE | SET NULL | SET DEFAULT | NO ACTION}]
        [ON UPDATE {CASCADE | SET NULL | SET DEFAULT | NO ACTION}]]
    [, [CONSTRAINT constraint_name] CHECK (condition)]
)
[ON COMMIT {DELETE | PRESERVE} ROWS]
```

#### **Parameter Descriptions**

| Parameter | Type | Description | Default |
|-----------|------|-------------|---------|
| `GLOBAL TEMPORARY` | keyword | Creates a temporary table | FALSE |
| `IF NOT EXISTS` | keyword | Skip creation if table exists | FALSE |
| `qualified_table_name` | identifier | Hierarchical table name (up to 3 levels) | Required |
| `column_name` | identifier | Column identifier | Required per column |
| `data_type` | type | ScratchBird data type specification | Required per column |
| `DEFAULT` | expression | Default value for column | NULL |
| `GENERATED ALWAYS AS IDENTITY` | constraint | Auto-incrementing column, no user override (INT/BIGINT/UUID) | No identity |
| `GENERATED BY DEFAULT AS IDENTITY` | constraint | Auto-incrementing column, allows user override (INT/BIGINT/UUID) | No identity |
| `START WITH` | option | Initial value for numeric identity columns | 1 |
| `INCREMENT BY` | option | Step value for numeric identity columns | 1 |
| `GENERATOR` | option | UUID generator function for UUID identity columns | Sequential numeric |
| `NOT NULL` | constraint | Prevent NULL values | Allow NULL |
| `UNIQUE` | constraint | Unique value constraint | No constraint |
| `PRIMARY KEY` | constraint | Primary key designation | No primary key |
| `CHECK` | constraint | Boolean validation expression | No check |
| `REFERENCES` | constraint | Foreign key reference | No reference |
| `COLLATE` | option | Character collation sequence | Database default |
| `ON COMMIT` | option | Temporary table behavior | PRESERVE ROWS |

```sql

-- Identity column with custom start and increment

    order_date DATE DEFAULT CURRENT_DATE,
    total_amount DECIMAL(10,2) NOT NULL
);

-- Identity column with UUID generator
CREATE TABLE audit_log (
    log_id UUID GENERATED ALWAYS AS IDENTITY 
        (GENERATOR UUID_GENERATE_V4()) PRIMARY KEY,
    table_name VARCHAR(100) NOT NULL,
    operation VARCHAR(10) NOT NULL,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    user_id INTEGER
);

-- Multiple identity columns in hierarchical schema
CREATE TABLE finance.accounting.transactions (
    transaction_id BIGINT GENERATED ALWAYS AS IDENTITY 
        (START WITH 100000 INCREMENT BY 1) PRIMARY KEY,
    batch_id INTEGER GENERATED BY DEFAULT AS IDENTITY 
        (START WITH 1 INCREMENT BY 1),
    account_code VARCHAR(20) NOT NULL,
    amount DECIMAL(15,2) NOT NULL,
    transaction_date DATE NOT NULL,
    description VARCHAR(500)
);

-- Identity column comparison: ALWAYS vs BY DEFAULT
CREATE TABLE example_always (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(50)
);

CREATE TABLE example_by_default (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(50)
);

-- Insert behavior differences:
-- ALWAYS: INSERT INTO example_always (name) VALUES ('Test');  -- Works
-- ALWAYS: INSERT INTO example_always (id, name) VALUES (999, 'Test');  -- ERROR!

-- BY DEFAULT: INSERT INTO example_by_default (name) VALUES ('Test');  -- Works, uses generated value
-- BY DEFAULT: INSERT INTO example_by_default (id, name) VALUES (999, 'Test');  -- Works, uses provided value
```

##### **GENERATED IDENTITY Supported Data Types**

GENERATED IDENTITY columns support the following data types in ScratchBird:

**Numeric Types (Sequential):**
```sql
-- Small integers (recommended for small tables)
id SMALLINT GENERATED ALWAYS AS IDENTITY

-- Standard integers (most common)
id INTEGER GENERATED ALWAYS AS IDENTITY (START WITH 1 INCREMENT BY 1)

-- Large integers (recommended for high-volume tables)
id BIGINT GENERATED ALWAYS AS IDENTITY (START WITH 1000000 INCREMENT BY 1)
```

**UUID Type (Globally Unique):**
```sql
-- UUID with default V4 generator
id UUID GENERATED ALWAYS AS IDENTITY

-- UUID with specific generator function
id UUID GENERATED ALWAYS AS IDENTITY (GENERATOR UUID_GENERATE_V4())

-- UUID with timestamp-based generator (V1)
id UUID GENERATED ALWAYS AS IDENTITY (GENERATOR UUID_GENERATE_V1())

-- UUID allowing user override
id UUID GENERATED BY DEFAULT AS IDENTITY (GENERATOR UUID_GENERATE_V4())
```

**Data Type Recommendations:**
- **INTEGER/BIGINT**: Use for sequential IDs, auto-incrementing primary keys, high-performance scenarios
- **UUID**: Use for distributed systems, replication, globally unique identifiers, security-sensitive applications
- **BIGINT**: Preferred for high-volume tables expecting > 2 billion rows
- **UUID**: Preferred for tables that may be replicated across multiple databases

**Examples by Use Case:**
```sql
-- High-performance OLTP system
CREATE TABLE orders (

    customer_id INTEGER NOT NULL,

-- Mixed approach for audit trail

```

### ALTER TABLE

Modifies the structure of an existing table by adding, dropping, or changing columns and constraints.

#### **Syntax**
```sql
ALTER TABLE qualified_table_name
{
    ADD [COLUMN] column_definition |
    DROP [COLUMN] column_name |
    ALTER [COLUMN] column_name {
        SET DEFAULT expression | 
        DROP DEFAULT | 
        TYPE new_data_type |
        SET GENERATED {ALWAYS | BY DEFAULT} |
        SET START WITH value |
        SET INCREMENT BY value |
        RESTART [WITH value] |
        DROP IDENTITY
    } |
    ADD [CONSTRAINT constraint_name] table_constraint |
    DROP CONSTRAINT constraint_name
}
```

#### **ALTER Operations**

##### **Add Column**
```sql
-- Add single column
ALTER TABLE customers 
ADD phone_number VARCHAR(20);

-- Add column with constraints
ALTER TABLE customers
ADD COLUMN address TEXT DEFAULT 'Not specified',
ADD COLUMN country_code CHAR(2) DEFAULT 'US' 
    CHECK (country_code IN ('US', 'CA', 'MX'));
```

##### **Drop Column**
```sql
-- Drop single column
ALTER TABLE customers 
DROP COLUMN phone_number;

-- Drop multiple columns
ALTER TABLE customers
DROP old_field1,
DROP old_field2;
```

##### **Modify Column**
```sql
-- Change column default
ALTER TABLE customers
ALTER COLUMN country_code SET DEFAULT 'CA';

-- Remove column default
ALTER TABLE customers
ALTER COLUMN address DROP DEFAULT;

-- Change column type
ALTER TABLE customers
ALTER COLUMN phone_number TYPE VARCHAR(30);
```

##### **Modify Identity Columns**
```sql
-- Add identity to existing column
ALTER TABLE customers
ALTER COLUMN customer_id 
SET GENERATED ALWAYS AS IDENTITY (START WITH 1000 INCREMENT BY 1);

-- Change identity generation type
ALTER TABLE orders
ALTER COLUMN order_id SET GENERATED BY DEFAULT;

-- Modify identity start value
ALTER TABLE products
ALTER COLUMN product_id SET START WITH 50000;

-- Modify identity increment
ALTER TABLE transactions
ALTER COLUMN transaction_id SET INCREMENT BY 10;

-- Restart identity sequence
ALTER TABLE audit_log
ALTER COLUMN log_id RESTART WITH 100000;

-- Restart identity with current maximum + 1
ALTER TABLE customers
ALTER COLUMN customer_id RESTART;

-- Remove identity from column (convert to regular column)
ALTER TABLE temp_table
ALTER COLUMN temp_id DROP IDENTITY;

-- Add numeric identity column to existing table
ALTER TABLE legacy_customers
ADD COLUMN new_id BIGINT GENERATED ALWAYS AS IDENTITY 
    (START WITH 1 INCREMENT BY 1) PRIMARY KEY;

-- Add UUID identity column to existing table  
ALTER TABLE user_profiles
ADD COLUMN profile_uuid UUID GENERATED ALWAYS AS IDENTITY 
    (GENERATOR UUID_GENERATE_V4()) UNIQUE;

-- Convert regular column to numeric identity with hierarchy
ALTER TABLE finance.accounting.ledger_entries
ALTER COLUMN entry_id 
SET GENERATED BY DEFAULT AS IDENTITY 
    (START WITH 1000000 INCREMENT BY 1);

-- Convert regular column to UUID identity
ALTER TABLE session_data
ALTER COLUMN session_id 
SET GENERATED ALWAYS AS IDENTITY 
    (GENERATOR UUID_GENERATE_V4());
```

##### **Add Constraints**
```sql
-- Add primary key
ALTER TABLE customers
ADD CONSTRAINT pk_customers PRIMARY KEY (customer_id);

-- Add foreign key with hierarchical reference
ALTER TABLE orders
ADD CONSTRAINT fk_orders_customer
FOREIGN KEY (customer_id) 
REFERENCES crm.customers.customer_master(customer_id)
ON DELETE CASCADE;

-- Add check constraint
ALTER TABLE orders
ADD CONSTRAINT chk_order_amount
CHECK (total_amount > 0);
```

##### **Drop Constraints**
```sql
-- Drop constraint by name
ALTER TABLE orders
DROP CONSTRAINT fk_orders_customer;

-- Drop primary key
ALTER TABLE customers
DROP CONSTRAINT pk_customers;
```

### DROP TABLE

Permanently removes a table and all its data from the database.

#### **Syntax**
```sql
DROP TABLE [IF EXISTS] qualified_table_name
```

#### **Examples**
```sql
-- Standard drop
DROP TABLE customers;

-- Safe drop with hierarchical schema
DROP TABLE IF EXISTS finance.accounting.temp_calculations;

-- Drop temporary table
DROP TABLE session_data;
```

## Administrative Notes

### Backup/Restore Considerations

#### **Table Backup**
- **Metadata Backup**: All table definitions stored in system catalog
- **Data Backup**: Full table data included in standard backup
- **Schema Dependencies**: Hierarchical schema structure preserved
- **Constraint Dependencies**: Foreign key relationships maintained
- **Index Dependencies**: All table indexes backed up with table

#### **Restore Process**
```sql
-- Tables restored in dependency order
-- 1. Parent tables (referenced by foreign keys)
-- 2. Child tables (containing foreign keys)
-- 3. Indexes and constraints recreated
-- 4. Schema hierarchy validated
```

### Security Implications

#### **Table-Level Security**
- **Schema-Based Access**: Security enforced at schema level
- **Owner Permissions**: Table creator has full permissions
- **GRANT/REVOKE**: Standard SQL permissions model
- **System Tables**: Protected from user modification

#### **Access Control**
```sql
-- Grant table permissions
GRANT SELECT, INSERT, UPDATE, DELETE ON customer_profiles TO role_sales;
GRANT SELECT ON financial.transactions.transaction_log TO role_auditor;

-- Schema-level permissions
GRANT USAGE ON SCHEMA finance.accounting TO role_accounting;
```

#### **Table Statistics**
- **Row Count**: Maintained automatically
- **Page Count**: Tracked for storage optimization
- **Index Statistics**: Selectivity calculations
- **Access Patterns**: Query optimizer statistics

#### **Monitoring Queries**
```sql
-- Table size and statistics
SELECT 
    r.RDB$RELATION_NAME,
    r.RDB$SCHEMA_NAME,
    s.RDB$RELATION_ID,
    s.RDB$RECORD_COUNT,
    s.RDB$PAGE_COUNT
FROM RDB$RELATIONS r
JOIN RDB$STATISTICS s ON r.RDB$RELATION_NAME = s.RDB$RELATION_NAME
WHERE r.RDB$SYSTEM_FLAG = 0;

-- Table access patterns
SELECT 
    m.MON$TABLE_NAME,
    m.MON$RECORD_SEQ_READS,
    m.MON$RECORD_IDX_READS,
    m.MON$RECORD_INSERTS,
    m.MON$RECORD_UPDATES,
    m.MON$RECORD_DELETES
FROM MON$TABLE_STATS m
ORDER BY m.MON$RECORD_SEQ_READS DESC;
```

### Troubleshooting Tips

#### **Common Issues**

**1. Schema Not Found**
```sql
-- Problem: Cannot create table in non-existent schema
CREATE TABLE finance.new_table (id INTEGER);
-- Error: Schema 'finance' does not exist

-- Solution: Create schema first
CREATE SCHEMA finance;
CREATE TABLE finance.new_table (id INTEGER);
```

**2. Foreign Key Constraint Violations**
```sql
-- Problem: Cannot create foreign key to non-existent table
-- Solution: Create referenced table first or use conditional DDL
CREATE TABLE IF NOT EXISTS parent_table (id INTEGER PRIMARY KEY);
CREATE TABLE child_table (
    id INTEGER PRIMARY KEY,
    parent_id INTEGER REFERENCES parent_table(id)
);
```

**3. Hierarchical Schema Depth Limits**
```sql
-- Problem: Exceeding maximum schema depth (11 levels)
-- Error: Schema hierarchy too deep

-- Solution: Reorganize schema structure
-- Instead of: a.b.c.d.e.f.g.h.i.j.k.l.table_name
-- Use: department.division.section.table_name
```

**4. Database Link Reference Issues**
```sql
-- Problem: Database link not accessible
-- Solution: Verify link exists and is accessible
SELECT * FROM RDB$DATABASE_LINKS WHERE RDB$LINK_NAME = 'remote_link';

-- Test link connectivity
SELECT COUNT(*) FROM remote_table@remote_link;
```
