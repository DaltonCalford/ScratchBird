# Process and Agents

## Agent Starting Context

When an AI session is started, it will be given its role and the current task. The agent should use the following documents to understand its duties, the project's status, and the rules it needs to follow.

- **This Document:** This document (`project/PROCESS_AND_AGENTS.md`) defines the roles and responsibilities of each agent, the development process, and the reporting requirements.
- **Project Status:** The `STATUS.md` file in the root directory provides a summary of the project's current status.
- **Implementation Plan:** The `project/plan/IMPLEMENTATION_PLAN.md` file outlines the development stages and the tasks for each phase.
- **Coding Standards:** The `docs/development/CODING_STANDARDS.md` document defines the coding standards for the project.
- **Build Instructions:** The `docs/development/BUILD_INSTRUCTIONS.md` document provides instructions for building the project.

## Roles
- Project Reviewer (Agent): Monitors commits and plans, prevents deviation from `AUTHORITATIVE_IMPLEMENTATION_PLAN.md` and Stage plans.
- Code Implementor (Agent A): Implements per specs, clarifies when needed, integrates feedback from Agent B, ensures Agent C tests pass or documents exceptions.
- Code Reviewer (Agent B): Performs deep reviews for correctness, security, memory safety, and spec compliance. Does not modify code.
- Test Writer (Agent C): Authors performance/hardening/edge-case tests. Core validation for Agent A. May mark tests as future if feature belongs to later stages.

## Process
1. Review authoritative plan and current Stage plan.
2. Implement by smallest viable phases; keep edits aligned to Stage scope.
3. Update progress logs in `project/progress/`.
4. Create/update tests with each implementation step.
5. Run sanitizers (ASAN/TSAN/UBSAN) and static analysis routinely.
6. Open change requests in `docs/change_requests/` for any deviations.

## Reporting
- All reports generated by agents must be saved to their respective directories.
- Code review reports are to be saved in `project/reviews/`.
- Test reports are to be saved in `project/tests/`.
- File names should be based on the task and date (e.g., `agent_b_code_review_2025-09-08.md`).

## Quality Gates
- All tests passing for current Stage scope
- No P0 issues open (crash, data loss, security)
- Memory and resource safety proven
- Documentation changes merged with code

## Naming
This repository uses a Stage scheme `1.x.yy` for Alpha. Stage 0 (1.0.xx) is completed foundation. Stage 1 (1.1–1.9) is the new focus.
